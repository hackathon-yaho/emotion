# 아직 못 한 것 — 무엇이 막고 있나

> **작성 2026-09-05. 이 파일은 스냅샷이지 단일 출처가 아니다.**
> 항목의 진짜 출처는 **Phase 문서의 그 줄**이다. 여기를 고치고 Phase 문서를 안 고치면 **여기가 틀린다** — 반대는 괜찮다.
>
> ```sh
> grep -n "⏳" backend/docs/phase-*.md          # 끝내지 못한 완료 기준
> grep -n "^- \[ \]" backend/docs/phase-*.md   # 아직 안 한 작업
> grep -L "상태: ✅" docs/request/*/*.md        # 회신을 기다리는 요청
> ```

**Phase 1~7의 코드와 검증이 끝났다.** 여기 남은 것은 **값 하나 또는 상대의 회신 하나**가 오면 그 자리에서 끝나는 것들이다. 그래서 "할 일" 순이 아니라 **막는 것** 순으로 묶었다 — 하나가 풀리면 몇 개가 같이 열리는지가 보여야 우선순위가 정해진다.

## ② `GOOGLE_API_KEY` — AI가 넣어야 한다

**막는 것: 2건.**

> **변수명이 두 번 바뀌었다** (2026-09-05). `ANTHROPIC_API_KEY` → `OPENAI_API_KEY` → **`GOOGLE_API_KEY`**(Gemini 무료 티어). AI 회신에는 `OPENAI_API_KEY`로 적혀 있지만 **그 뒤 커밋이 Gemini로 또 바꿨고**, `ai-server/app/config.py`가 실제로 읽는 이름은 `google_api_key`다 — **코드를 따랐다.** SDK 의존성이 `openai>=2.0`인 것은 Gemini의 OpenAI 호환 엔드포인트를 쓰기 때문이다.

| 못 한 것 | 근거 | 지금 상태 |
| --- | --- | --- |
| **진짜 문장으로 관찰 1건** | `phase-4` | **대역 서버로 성공 경로는 확인했다**(2026-09-05) — 판정·evidence·근거 연결·목록 노출까지. LLM이 쓴 문장만 못 봤다 |
| **진짜 문장으로 요약 1건** | `phase-2` | 같음. 대역 서버로 `summary`가 종료 응답에 실리는 것까지 확인 |

> **백엔드가 더 할 일은 없다.** 진짜 AI서버는 키가 없어 `422 SENTENCE_REJECTED(call_failed)`로 떨어지고, 우리 쪽은 그걸 **"문장이 없으면 관찰도 없다"**로 정확히 처리한다(템플릿 폴백 없음).

## 백엔드가 지금 당장 만들 것

**없다.** Phase 1~7의 코드와 검증이 끝났고, 남은 것은 **계정 두 개(⑦)와 위 ①~⑥의 값·회신**이다.

코드는 값이 오는 순간 그대로 돈다 — 기다리는 동안 백엔드가 더 만들 것은 없다.

> **여기에 "남은 것 N건"을 적지 않는다.** 손으로 센 숫자는 다음 작업이 끝나는 순간 틀리고, 틀린 줄 모른 채 "다 했다"의 근거가 된다 — 백엔드가 `tag-gap-endpoint.md`를 놓친 경위가 그것이었다(루트 `CLAUDE.md`). **세는 것은 맨 위 grep이 한다.**
