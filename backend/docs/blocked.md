# 아직 못 한 것 — 무엇이 막고 있나

> **작성 2026-09-05. 이 파일은 스냅샷이지 단일 출처가 아니다.**
> 항목의 진짜 출처는 **Phase 문서의 그 줄**이다. 여기를 고치고 Phase 문서를 안 고치면 **여기가 틀린다** — 반대는 괜찮다.
>
> ```sh
> grep -n "⏳" backend/docs/phase-*.md          # 끝내지 못한 완료 기준
> grep -n "^- \[ \]" backend/docs/phase-*.md   # 아직 안 한 작업
> grep -L "상태: ✅" docs/request/*/*.md        # 회신을 기다리는 요청

**Phase 1~7의 코드와 검증이 끝났다.** 여기 남은 것은 **값 하나 또는 상대의 회신 하나**가 오면 그 자리에서 끝나는 것들이다. 그래서 "할 일" 순이 아니라 **막는 것** 순으로 묶었다 — 하나가 풀리면 몇 개가 같이 열리는지가 보여야 우선순위가 정해진다.

## ① Hume — 계정과 키는 왔다. 남은 것은 **Config**다

**팀장이 계정을 만들고 키를 `.env`에 넣었다** (2026-09-05). 원래 계획은 AI 소유였는데(`response/backend/hume-account-setup.md`) 실제로는 팀장이 만들었다 — **Config 소유자가 다시 정해져야 한다.**

**토큰 발급은 실제로 돌았다** — `POST /api/session/start`가 실물 토큰으로 **201**을 낸다(EVI 시간 0초, 소켓을 안 열었다).

> **그 과정에서 결함 1건을 잡았다** — Hume 토큰 엔드포인트가 **200에 `Content-Type`을 안 싣는다.** 응답을 `Map`으로 받으면 Spring이 변환기를 못 골라 `UnknownContentTypeException`이 나고, **겉으로는 키가 틀린 것과 똑같은 503**으로 보인다. `String`으로 받아 직접 파싱하도록 고치고 회귀 테스트로 묶었다. **대역으로는 절대 안 보이는 종류**다.

## ② `GOOGLE_API_KEY` — 값은 들어갔다. 이제 **모델명이 안 맞는다**

**막는 것: 2건.** 2026-09-05에 팀장이 키를 받아 `ai-server/.env`에 넣었다. 다만 같은 파일의 `AI_MODEL_*`이 **Claude 모델명 그대로**(`claude-haiku-4-5` 등)라 Gemini 엔드포인트에 그 이름을 보내게 된다 — `AI_ANALYZE_TIMEOUT_MS=400`도 Gemini 실측 p95(5473ms)보다 짧다. AI에 확인 요청했다(`../../docs/request/ai/gemini-switch-mismatch.md` ⏳).

> **변수명이 두 번 바뀌었다** (2026-09-05). `ANTHROPIC_API_KEY` → `OPENAI_API_KEY` → **`GOOGLE_API_KEY`**(Gemini 무료 티어). AI 회신에는 `OPENAI_API_KEY`로 적혀 있지만 **그 뒤 커밋이 Gemini로 또 바꿨고**, `ai-server/app/config.py`가 실제로 읽는 이름은 `google_api_key`다 — **코드를 따랐다.** SDK 의존성이 `openai>=2.0`인 것은 Gemini의 OpenAI 호환 엔드포인트를 쓰기 때문이다.
