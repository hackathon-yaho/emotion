# 1. 반복된 모양 여섯 가지

**결함 하나하나는 다 달랐는데 모양은 여섯 개뿐이었다.** 새 코드를 짤 때 이 여섯 개를 먼저 물어보면 대부분 걸린다.

## ① 조용히 실패한다 — 정상 동작과 구분이 안 된다

**가장 많았고 가장 위험했다.** 오류가 안 나고, 화면이 안 깨지고, 로그도 조용하다. **기능만 없다.**

| 결함 | 겉으로 보이던 모습 |
| --- | --- |
| `resumedChatGroupId`를 채우는 주체가 없었다 | 이어하기가 **된다.** 이전 맥락만 안 온다 |
| 이어하기 후 `turnIndex`가 리셋되면 턴이 `unique`에 걸려 버려진다 | **202가 나간다.** 그 대화의 발화만 사라진다 |
| `AI_SERVER_BASE_URL`을 배포 후 안 바꾸면 | `summary: null`, 관찰 0건 — **둘 다 설계상 정상값이다** |
| Hume 토큰 응답에 `Content-Type`이 없다 | **키가 틀린 것과 똑같은 503** |
| GitHub 저장소 변수가 하나도 없었다 | 앱 웹 빌드가 **빈 키로** 나간다. 빌드는 성공한다 |
| `API_BASE_URL`이 비어 폴백이 `localhost:8080` | 배포본이 **조용히 자기 로컬을 부른다** |
| Hume Config의 `language_model`이 `null` | **Hume 내장 LLM이 그럴듯하게 대답한다.** 우리 AI서버만 안 불린다 |

**공통점**: 실패한 쪽이 **null이나 빈 값**이고, 그 값이 **계약상 허용된 값**이다.

> **그래서 규칙 하나** — **null이 허용되는 필드를 만들 때, 그 null이 "측정 실패"인지 "설정 누락"인지 구분할 방법을 같이 만든다.** 계약 §1-3이 null의 뜻을 적어둔 이유가 이것이다.

## ② 정상 경로에서는 절대 안 밟히는 코드

**정상 동작을 아무리 돌려도 안 나온다.** 방어선·오류 경로·기본값 경로에 몰려 있었다.

| 결함 | 왜 안 보였나 |
| --- | --- |
| `GET /api/trend`가 `range` 생략 시 **500** | 테스트를 `range=7d`로만 짰다. **생략이 가장 흔한 호출인데** |
| `OPTIONS` 프리플라이트가 401 | 인증 제외를 **경로**로만 뒀다. 메서드는 안 봤다 |
| 깨진 JSON이 500 (AI가 5xx를 3회 재시도한다) | 정상 본문만 보냈다 |
| 카카오 `app_id` 대조가 없었다 | **정상 로그인만 하면 통과한다.** 남의 앱 토큰으로 들어와야 드러난다 |
| AI서버의 fail-closed 401 경로가 **500** | 모르는 세션·`ended`에서만 밟힌다 |

> **그래서 규칙 하나** — **오류 경로와 기본값 경로는 테스트를 따로 쓴다.** 특히 **기본값 경로**가 실서비스의 정상 경로인 경우가 많다(`range` 생략, 대기열 꺼짐).

## ③ 베낀 것이 어긋난다

**단일 출처를 두고도 "편의상" 옮겨 적은 것들이 전부 낡았다.**

| 결함 | 무엇을 베꼈나 |
| --- | --- |
| Phase 문서의 응답 필드 나열이 **5곳에서** 계약과 달랐다 | 계약 스키마 |
| 회신 현황에 "4건 전부 완료"라 적어둬 **5번째 요청을 놓쳤다** | 미회신 개수 |
| `phase-7` 환경변수 목록에 없어진 `KAKAO_APP_ID`가 남고 **필수 `KAKAO_REST_API_KEY`가 빠졌다** | `application.yml` |
| `grep -L "✅"`가 본문의 ✅ 하나에 미회신 요청을 숨겼다 | (규칙 자체의 결함) |
| LLM 키 이름이 `ANTHROPIC` → `OPENAI` → `GOOGLE`로 두 번 바뀌며 문서 3곳이 낡았다 | 상대 회신 문서 |

> **그래서 규칙 하나** — **고치는 방향은 "규칙을 더한다"가 아니라 "베낀 것을 지운다"다.** Phase 문서는 필드를 지우고 계약 §번호만 가리키게 했고, 회신 현황은 개수를 지우고 `grep` 한 줄로 바꿨다.

## ④ 대역으로는 안 보인다 — 실물에서만 드러난다

| 결함 | 대역이 가린 것 |
| --- | --- |
| Hume 토큰 응답에 `Content-Type`이 없다 | 목은 **Content-Type을 붙여서** 준다 |
| 관찰·요약의 성공 경로가 **한 번도 안 돌았다** | 단위 테스트가 **클라이언트 자체를 목으로** 바꿔 HTTP 계층이 실행된 적이 없었다 |
| `gapAvg`가 `0.80000000000000000000` | Postgres `avg()`의 스케일. 목은 `0.80`을 준다 |
| `gradlew`에 실행 비트가 없었다(`100644`) | Windows에서는 안 쓴다. **리눅스 Docker 빌드가 통째로 죽는다** |

> **그래서 규칙 하나** — **목으로 확인한 것은 "돈다"가 아니라 "우리 쪽 코드가 돈다"이다.** 성공 경로를 한 번은 실물이나 대역 **서버**로 통과시킨다(클라이언트 목이 아니라).

## ⑤ 값의 수명이 서로 다르다

**두 시스템이 같은 것을 가리키는데 유효 기간이 다르면, 한쪽 기준으로 판단하는 순간 틀린다.**

| 결함 | 어긋난 두 수명 |
| --- | --- |
| `resumableUntil`을 `ended_at + 30분`으로 계산 | **열린 세션은 `ended_at`이 NULL이다.** `started_at` 기준으로 바꾸면 이번엔 TC-22가 깨진다 → **마지막 턴의 `occurred_at`**이 답이었다 |
| 대기열 정원을 우리 열린 세션 행으로 세면 | **Hume은 비활성 2분에 닫고 우리 행은 30분 열려 있다** → 빈 자리를 두고 사람을 돌려보낸다 |
| 탈퇴·삭제 시 관찰 재계산을 baseline보다 먼저 | **분모(`user_avg_gap`)가 나중에 갱신**되어 비율이 옛 평균으로 남는다 |
| 탈퇴에서 `account_profile`을 먼저 지우면 | **어느 `account`였는지 알 방법이 사라진다** |

> **그래서 규칙 하나** — **"지금 살아 있는 것"을 판단할 때는 그 판단을 실제로 강제하는 쪽에 묻는다.** 정원은 Hume에, 마지막 활동은 턴에.

## ⑥ 테스트가 자기 자신을 속인다

**통과했는데 아무것도 확인하지 않은 경우들이다.**

| 결함 | 무엇이 확인되지 않았나 |
| --- | --- |
| 롤백 테스트가 **테스트 트랜잭션을 공유**했다 | 서비스의 롤백이 테스트에 안 보인다 — **정작 확인하려던 경계** |
| JdbcTemplate 검증이 **플러시 안 된 JPA 삽입**을 못 봤다 | 방금 저장한 것이 안 보여 "저장 안 됨"으로 읽힌다 |
| `ops_error_log`의 `REQUIRES_NEW` 행이 롤백을 넘어 남았다 | 다른 테스트가 남긴 행을 세고 있었다 |
| 세션 테스트가 **실제 `api.hume.ai`로 나가고 있었다** | 오프라인이면 깨지고, 매 테스트가 외부에 의존한다 |
| 대기열을 **켠 경로만** 테스트하면 | **기본값이 꺼짐이라 평소 도는 쪽이 검증되지 않는다** |

> **그래서 규칙 하나** — **테스트가 통과했을 때 "무엇이 확인됐나"를 한 번 되묻는다.** 특히 롤백·격리·기본값처럼 **"안 일어나는 것"을 확인하는 테스트**가 위험하다.

# 3. 검증에서 실제로 효과가 있었던 것

**테스트 개수보다 이 네 가지가 결함을 더 많이 잡았다.**

## ① 실물로 한 번 돌려보기

목이 가린 것이 **네 건**이었다(모양 ④). `curl`로 실서버에 한 번 쏘는 것이 단위 테스트 열 개보다 자주 잡았다.

- AI서버의 고정 픽스처를 그대로 `curl`로 → 재시도와 충돌이 실서버에서 갈렸다
- 배포 이미지로 `PORT=10000` 주입 기동 → `gradlew` 실행 비트
- Hume 키로 실제 호출 → `Content-Type` 없음

## ② 없는 것을 만들어서 확인하기

**"상대가 준비 안 돼서 못 한다"가 실제로는 "도구가 없어서 못 한다"였던 것이 두 건.** 스크래치패드에 20~40줄짜리를 만들어 닫았다.

- **고장 주입 프록시** — `/internal/turns`를 백엔드로 넘긴 뒤 503으로 바꿔 돌려준다. 같은 턴을 8회 받고도 **행 2개, 충돌 0건**
- **대역 AI서버** — 관찰·요약의 **성공 경로가 한 번도 안 돌았던 것**을 그때 발견했다

> **백엔드 코드에 고장 스위치를 넣지 않았다.** 그런 코드는 배포까지 따라간다.

## ③ 문서를 코드에서 다시 뽑기

`phase-7`의 환경변수 목록을 **`application.yml`에서 다시 생성**하자 낡은 항목이 바로 드러났다(모양 ③).

## ④ 상대의 지적을 우리 코드에 적용해 보기

AI에 보낸 로그 위생 지적을 **앱이 읽고 자기 코드를 훑어** `sessionId`가 주소창에 있는 것을 찾아왔다. 우리도 AI의 `chat_group_id` 회신을 받고 **`resumedChatGroupId`의 빈 값 규칙**을 확정했다.
