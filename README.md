# 감정 케어 보이스 저널

말로 하루를 이야기하면 AI가 **말투에서** 감정을 읽어 실시간 대화 상대가 되어주고, 쌓인 대화에서 **내가 몰랐던 패턴을 발견해 돌려주며**, 사용자가 원하면 **그 관찰에 근거한 생활 조정을 제안**하는 모바일 서비스.

원티드 AI Championship 2026 제출 프로젝트 — 앱 1 · 백엔드 1 · AI 개발자 1, 총 3인 협업. 제출 마감 **2026-09-20**.

모든 요구사항과 설계 결정의 단일 진실 공급원은 [`docs/00-context/prd.md`](docs/00-context/prd.md) 입니다. 프로젝트를 처음 본다면 [`docs/README.md`](docs/README.md) 부터 읽으세요 — 문서 지도와 역할별 읽는 순서가 정리되어 있습니다.

## 저장소 구조

이 프로젝트는 3개의 독립 배포 서비스로 구성됩니다. 각자 자신이 만든 서비스를 직접 배포·운영합니다.

| 경로 | 서비스 | 담당 | 스택 |
| --- | --- | --- | --- |
| [`app/`](app/) | 모바일 앱 — EVI SDK 연동, 대화 UI, 트렌드 그래프 | 앱 | React Native 또는 Flutter (담당자 결정) |
| [`backend/`](backend/) | 카카오 인증 · 턴 로그 · 패턴 배치 · 대시보드 API | 백엔드 | Java / Spring Boot · Supabase(PostgreSQL) |
| [`ai-server/`](ai-server/) | Hume CLM 엔드포인트 · valence 산출 · 갭 계산 · 프롬프트 · 평가 세트 | AI 개발자 | 담당자 결정 (Hume CLM 공식 예제는 Python/FastAPI) |

세 서비스 간 계약은 [`docs/02-architecture/api-contract.md`](docs/02-architecture/api-contract.md)에 정의되어 있습니다 — ① 앱↔백엔드 ② AI서버↔백엔드(내부) ③ Hume↔AI서버(외부·변경 불가).

## 핵심 설계 원칙

> **절대 감정을 단정하지 않는다. 갭만 본다.** 갭 = |텍스트 valence − 음성 valence|. "슬픔 78%" 같은 절대 감정 상태를 주장하지 않고, 두 채널의 차이가 임계를 넘으면 AI가 **되묻는다**(FR-022·030). 갭 수치는 대화 화면에 노출하지 않는다.

> **패턴의 존재는 코드가 판정하고, LLM은 표현만 한다.** 관찰은 "같은 태그 3회 이상 AND 개인 평균 갭의 1.5배 이상"일 때만 생성되고(FR-051), 조건 미달이면 침묵한다(FR-052). 모든 관찰에는 evidence가 붙고, 관찰 문장 ↔ evidence 숫자 불일치는 0건이어야 한다.

> **음성 원본은 저장하지 않는다.** 우리 서버는 음성 파일을 수신하지도 저장하지도 않는다(FR-041). 위기 감지(F4)는 어떤 스코프 컷에서도 자르지 않는다.

자세한 배경은 [`docs/00-context/prd.md`](docs/00-context/prd.md) §1·§4·§9 참조.
