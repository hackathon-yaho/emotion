## 1. 계정은 AI가 소유합니다 — 동의합니다

이유 세 가지 다 맞습니다. 특히 두 번째가 결정적입니다. Config는 CLM URL이 바뀔 때마다 고쳐야 하는데, **무료 ngrok은 재시작마다 주소가 바뀝니다.** 통합 기간에 하루에도 몇 번 고치게 되고, 그때마다 왕복이 생기면 그것만으로 반나절이 갑니다.

**결제도 그 계정에서 하겠습니다.** 카드 주체와 정산은 팀 내부 문제로 두고, 기술 요건인 "결제가 Config를 만든 계정에서 이뤄질 것"만 지키겠습니다.

## 2. 플랜 — 490분에서는 Creator가 Starter보다 쌉니다

**요청서의 판단 기준("490분을 어느 쪽이 싸게 넘기는지")대로 계산했습니다.**

| 플랜 | 월 요금 | 포함 분수 | 초과 단가 | **490분 총액** | 동시 접속 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Free | $0 | 5 | $0.06 | — (성립 불가) | 1 |
| Starter | $3 | 40 | $0.07 | **$34.50** | 5 |
| **Creator** | **$7** | **200** | **$0.07** | **$27.30** | **5** |
| Pro | $70 | 1,200 | $0.06 | $70.00 | 10 |

**분기점은 약 97분입니다.** 그 위로는 Creator가 쌉니다 — 포함 분수 차이(160분 × $0.07 = $11.20)가 월 요금 차이($4)보다 크기 때문입니다. 우리는 490분을 잡고 있으니 한참 위입니다.

**Creator 월 요금에 3자 문서 간 불일치가 있습니다.** 요금 페이지에서는 $7로 읽혔는데 어떤 정리 글은 $14로 적습니다. **다만 결론은 바뀌지 않습니다** — $14로 계산해도 490분 총액이 $34.30으로 Starter($34.50)와 사실상 같습니다. **비싸지지 않으면서 포함 분수가 5배**이므로, 사용량 추정이 빗나갔을 때의 여유가 Creator 쪽에 있습니다.

승인 상한이 Creator이므로 **상한을 그대로 쓰는 것이 가장 싼 선택**인 셈입니다. 이건 흔치 않은 경우라 한 번 더 확인하실 만합니다.

**동시 접속은 Starter·Creator 모두 5**로 읽혔습니다. 필요값 3을 넘으므로 이 항목은 선택에 영향을 주지 않습니다.

## 3. 콘솔 실측 4건 — 아직 못 했습니다

**계정이 없어서입니다.** 가입은 브라우저에서 사람이 하는 단계라 제가 대신 진행할 수 없습니다. 위 표는 전부 **공개 요금 페이지에서 읽은 값**이고, PRD §2.5가 금지하는 "3자 문서를 확정값으로 쓰는 것"에 해당합니다. **결제 전에 콘솔에서 다시 봐야 합니다.**

가입이 끝나는 대로 네 가지를 확인해 이 문서에 덧붙이겠습니다.

1. 플랜별 포함 분수와 초과 단가
2. Creator 동시 접속 수
3. **신규 계정 $20 크레딧이 EVI 사용료에 적용되는지** — 적용되면 490분 중 300분 안팎이 덮여 PRD §11의 약 $37 추산이 절반 이하로 내려갑니다
4. 결제 수단 등록 위치와 워크스페이스 단위 결제 여부

**총액이 예상을 넘으면 결제 전에 알리겠습니다.**

## 4. 공유 시크릿 경로 — 비밀번호 관리자를 제안합니다

`INTERNAL_SHARED_SECRET`을 백엔드가 만들어 주시는 것에 동의합니다. 엔드포인트를 가진 쪽이 만드는 게 맞습니다.

**전달 경로는 이렇게 하시죠.**

| 우선순위 | 방법 | 이유 |
| --- | --- | --- |
| 1 | **비밀번호 관리자 공유 항목** (Bitwarden 무료 조직 등) | 접근 권한을 나중에 회수할 수 있고, 누가 언제 봤는지 남습니다 |
| 2 | **일회성 자동 삭제 링크** | 한 번 열리면 사라집니다. 링크 자체는 채팅으로 보내도 남는 게 없습니다 |

**카카오톡·이메일·이슈 코멘트는 쓰지 마세요.** 지워도 상대 기기와 백업에 남고, 나중에 검색으로 튀어나옵니다.

**같은 경로로 네 가지를 다 주고받으면 됩니다** — `INTERNAL_SHARED_SECRET`(백엔드 → AI), Hume 키 3종(AI → 백엔드), 카카오 JS 키(백엔드 → 앱). 경로를 하나로 정하자는 제안에 동의합니다.

**값 생성은 32바이트 난수를 base64로** 부탁드립니다. 사람이 읽을 필요가 없는 값이라 길이를 아낄 이유가 없습니다.

```bash
openssl rand -base64 32
```

## 5. 통합 1번 — AI서버 쪽도 준비됐습니다 (오늘부터 가능)

`GET /internal/sessions/{id}` 호출부가 **오늘 완성됐습니다.** 목표였던 9/6보다 하루 빠릅니다. 알려주신 네 가지 동작과 제 구현이 맞물리는지 대조했습니다.

| 백엔드가 준다고 하신 것 | AI서버 동작 |
| --- | --- |
| `X-Internal-Secret` 없거나 틀리면 401 | 헤더에 항상 실어 보냅니다 |
| 없는 `sessionId` → 404 | **401로 바꿔 Hume에 돌려줍니다** |
| `status: "ended"`도 200 | **401로 바꿔 Hume에 돌려줍니다** (계약 §3-4 그대로) |
| `lastTurnIndex`는 적재된 최대 인덱스, 지금은 항상 0 | 그 값에서 채번을 시작합니다. 0이면 첫 턴이 1입니다 |
| `recentObservations`는 빈 배열 | 빈 배열이면 F8 제안 경로만 비활성이고 나머지는 정상입니다 |

**터널을 여실 수 있으면 오늘 붙여보시죠.** Hume 키가 없어도 이 항목은 검증됩니다. 제 쪽 `.env`의 `BACKEND_BASE_URL`만 주신 주소로 바꾸면 됩니다.

추가로 **`/internal/turns`도 이미 돌아갑니다.** 통합 순서 2번을 이어서 할 수 있습니다. 특히 회신에서 제안드린 **재시도 시나리오**(저장은 성공시키고 응답만 버리기)를 한 번 해보시면 좋겠습니다 — 재시도 페이로드의 `occurredAt`이 최초 시도와 문자열까지 같은 것을 테스트로 고정해 뒀지만, **실제로 도는 걸 한 번은 봐야** 합니다.

## 6. 아직 검증하지 못한 것 (정직한 상태)

| 항목 | 상태 | 막는 것 |
| --- | --- | --- |
| Hume 실제 연결 | **미검증** — Config 없음 | 대화 전체 |
| Anthropic 실제 호출 | **미검증** — 키 없음 | 분석·응답·관찰·요약 (전부 목으로만 확인) |
| 백엔드 실제 연결 | **미검증** — 터널 전 | 없음 (오늘 가능) |

**코드는 서 있지만 한 번도 진짜 모델을 부른 적이 없습니다.** 프롬프트가 의도대로 동작하는지, 분석 호출이 400ms 안에 끝나는지(TC-12)는 키가 들어와야 알 수 있습니다. **이 세 줄이 지금 AI 파트의 실제 상태입니다.**

## 요청자 후속 작업

- **`INTERNAL_SHARED_SECRET` 생성과 전달** (경로는 위 4번)
- **터널 주소 공유** — 여시는 시점에 알려주시면 바로 붙이겠습니다
- Hume 키 3종은 **제가 계정을 만든 뒤 드립니다.** 콘솔 실측 4건도 그때 이 문서에 덧붙입니다
