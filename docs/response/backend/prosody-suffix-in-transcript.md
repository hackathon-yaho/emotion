## 결론

**짚으신 그대로입니다.** Hume은 CLM에 보내는 **user 발화 끝에 상위 3개 표정을 영문으로 붙입니다.** 우리 파서가 `content`를 가공 없이 들고 있어서 표에 적어 주신 다섯 경로(분석 입력·응답 이력·태그 대조·위기 규칙·백엔드 적재)가 전부 같은 문자열을 봤습니다.

**부탁하신 1번대로 파싱 시점에 한 번만 뗐습니다.** `Message`가 만들어지는 순간(`app/clm/request.py`) 잘라내므로 아래로 흐르는 모든 경로가 깨끗한 값을 받습니다. 배포했습니다.

## 네 가지 질문에 대한 답

### ① 파서에서 떼기 — 했습니다

제안하신 정규식을 거의 그대로 썼고 두 곳만 넓혔습니다.

```python
_EXPRESSION_SUFFIX = re.compile(r"\s*\{[A-Za-z][A-Za-z ,'()\-]*\}\s*$")
```

- **괄호 허용** — Hume 표정 이름에 `Surprise (positive)`처럼 괄호가 들어가는 것이 있습니다
- **영문자로 시작해야 함** — 빈 `{}`나 기호로 시작하는 것은 안 뗍니다

지켜지는 것은 테스트로 묶었습니다(13건).

| 입력 | 결과 |
| --- | --- |
| `…좀. {slightly doubtful, slightly calm, very slightly interested}` | 꼬리 제거 |
| `제가 {진짜 괜찮았어요} 라고 했잖아요` | **그대로** — 한글 중괄호는 사용자가 한 말 |
| `영어로 {hello} 라고 했어요 {slightly calm}` | **끝의 꼬리만** 제거 |
| 프로소디 점수 | **그대로** — 떼는 것은 텍스트 표현뿐 |

### ② Hume Config에서 끌 수 있나 — 없습니다

Hume Prompt Engineering 가이드에 **"상위 3개 표정을 각 User 메시지에 덧붙인다"**가 기본 동작으로만 나오고, 끄는 옵션은 문서에도 Config API 스키마에도 없습니다(Config 원문 전체를 읽어 확인했습니다). **파서 방어가 유일한 수단입니다.** 나중에 옵션이 생겨도 방어는 그대로 둡니다.

### ③ 실제 모양 — assistant에도 붙나

**문서상 user 메시지에만 붙습니다.** 다만 확인할 방법이 제한적이라, **떼는 쪽이 손해가 없어 역할을 가리지 않고 뗍니다.** assistant 문장은 우리 응답 모델이 한국어 1~3문장으로 만드므로 영문 중괄호가 끝에 올 일이 없습니다.

**다음 대화부터는 실측으로 보입니다.** 턴 로그에 `expressionSuffix=True/False`를 새로 남깁니다 — 꼬리 문자열은 프로소디의 텍스트 표현이라 **참/거짓만** 남깁니다(FR-092).

### ④ 언제부터 붙었나 — **처음부터로 보셔야 합니다**

Hume 기본 동작이라 켜고 끈 시점이 없습니다. **우리 CLM이 처음 실제 턴을 받은 2026-09-06 17:01(UTC)부터 이번 배포 직전까지, 저장된 모든 user 턴이 오염됐다고 보시면 됩니다.** 과거 턴을 하나하나 증명할 수는 없습니다 — 로그에는 발화를 남기지 않으므로(FR-092) 꼬리 유무도 안 남았습니다.

**저장된 턴 정리는 말씀하신 대로 시연 데이터를 새로 만드는 쪽을 권합니다.** 복호화–재암호화 일회성 작업보다 쌉니다.

## 갭은 얼마나 흔들렸나 — 재봤습니다

**가장 무겁다고 하신 부분이라 숫자로 확인했습니다.** 같은 문장을 꼬리 있음/없음으로 분석 모델에 2회씩 넣었습니다.

| 발화 | 붙인 꼬리 | 꼬리 없음 | 꼬리 있음 |
| --- | --- | --- | --- |
| 오늘 완전 괜찮았어요 | `{very tired, quite sad, slightly anxious}` | +1.00 · +1.00 | **+1.00 · +1.00** |
| 별일 없었어요 그냥 평범했어요 | `{quite distressed, moderately sad, …}` | 0.00 · 0.00 | **0.00 · 0.00** |
| 아 내가 이거 합격하면은 좀. | `{slightly doubtful, slightly calm, …}` | 0.00 · 0.00 | **+0.30 · +0.20** |
| 진짜 너무 신나요 내일 여행 가요 | `{very bored, quite tired, slightly sad}` | +1.00 · +1.00 | **+0.90 · 분석 실패** |

**걱정보다 작고, 한곳에 몰려 있습니다.**

- **말이 분명한 문장은 꼬리가 텍스트 valence를 못 움직였습니다.** 제품의 핵심 장면 — "말은 괜찮다는데 목소리는 지쳐 있다" — 은 +1.00 그대로라 **갭이 무너지지 않았습니다**
- **모호한 짧은 문장에서 ±0.1~0.3 흔들렸습니다.** 꼬리가 해석을 한쪽으로 기울입니다
- **분석이 한 번 실패했습니다**(1/8). 표본이 작아 단정하지 않지만, 입력에 영문 꼬리가 섞이면 JSON 출력이 흔들릴 수 있습니다

**지금까지 측정한 갭 값으로 결정한 것은 없습니다.** 임계값은 아직 임시값(0.85)이고 PRD §14-5의 20쌍 측정은 시작 전입니다. **이번 수정 뒤에 모으면 되므로 다시 해야 할 측정은 없습니다.**
