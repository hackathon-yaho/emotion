# 턴 0건 세션은 **감춥니다** — 지우지는 않습니다

- 출처: [`../app/duration-definition.md`](../app/duration-definition.md) 「곁다리 — 턴 0건 세션」 — *"빈 대화를 기록에서 감추실 거면 `turnCount == 0`으로 거르시면 됩니다. 지우는 것은 사용자 데이터라 앱이 정할 일이라고 봅니다."*
- 회신자: 앱
- 회신일: 2026-09-09

---

## 결정

**감춥니다.** 기록(S05)과 홈의 「지난 대화」에서 `turnCount == 0`인 세션을 걸러냅니다.

기록은 **돌아볼 것이 있는 대화**의 목록입니다. 턴 0건은 화면에 「요약이 없습니다 · 0초」로만 나오는데, 그건 대화가 아니라 **실패의 잔해**입니다(마이크가 막혔거나, 응답이 실패했거나, 열자마자 나간 경우). 첫 며칠 도그푸딩에서 그 줄이 여러 개 쌓이면 기록 화면이 실패 목록이 됩니다.

**지우지는 않습니다.** 사용자 데이터이고, 우리가 삭제 요청을 보낼 근거가 없습니다. 통계도 서버 값을 그대로 씁니다 — 설정의 탈퇴 문구는 `me.sessionCount`(서버)를 쓰므로 **감춘 세션도 그 수에 들어갑니다.** 그게 맞다고 봅니다. "지워질 것"은 실제로 지워지는 전부여야 합니다.

## 구현

`SessionSummary.isEmpty`(`turnCount == 0`) 하나로 두 화면이 같은 기준을 씁니다.

**걸러낸 뒤에 빈 상태를 판정합니다** — `d.items.every((s) => s.isEmpty)`. 순서를 뒤집으면 빈 세션만 있는 상태에서 목록이 통째로 사라지고 빈 상태 문구도 안 나옵니다. 홈도 걸러낸 뒤에 두 개를 고릅니다(그러지 않으면 빈 것이 자리를 차지해 실제 대화가 밀립니다).

**페이징은 서버 `total`을 그대로 씁니다.** 화면 단에서만 걸러내므로 `hasMore` 계산이 어긋나지 않습니다. 다만 **한 페이지가 전부 빈 세션이면 그 페이지는 아무것도 안 보입니다** — 20건 단위라 실사용에서 그럴 일은 없다고 보고 지금은 두겠습니다.

회귀 테스트 3건(`test/empty_session_test.dart`). 앱 테스트 128건 통과.

## `durationSec` 회신에 대해

**세 정의를 실제 세션에 돌려 비교한 표가 결정적이었습니다.** 저는 「하드컷으로 자르기」를 제안했는데, 그게 *31초 대화를 420초로 만들고* **클램프에 걸린 값은 전부 정확히 420이라 서로 다른 대화가 같은 숫자로 보인다**는 지적이 맞습니다. 제 제안이 틀렸습니다.

**951초의 정체가 「첫 턴 이전의 죽은 시간 909초」였다는 것**도 저희 쪽 원인과 이어집니다 — 그 세션은 「새로 시작」을 골랐는데 앱이 이어하기를 태운 것이었습니다(고쳤습니다, `8a39f3a`).

과소 계상(첫 발화 이전·마지막 꼬리가 빠지는 것)은 **지금 문제 삼지 않겠습니다.** 화면에 쓰는 숫자로 충분합니다.
