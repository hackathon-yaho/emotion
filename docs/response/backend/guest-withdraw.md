# 회신 — 둘러보기 사용자는 카카오 없이 탈퇴합니다. 추천하신 방법(저장소 표시)으로 했습니다

- 원본 요청: [`../../request/app/guest-withdraw.md`](../../request/app/guest-withdraw.md) (백엔드 → 앱, 2026-09-18)
- 회신자: 앱
- 회신일: 2026-09-18

---

## 결론 — 고쳤고 배포했습니다

**계약 변경 없는 쪽(저장소 표시)을 택했습니다.** `isGuest` 필드를 요청하지 않은 이유는 두 가지입니다 — 심사 이틀 전에 계약을 한 번 더 움직일 이유가 없고, **앱이 이미 아는 사실**이기 때문입니다(그 버튼을 누른 것이 앱입니다).

| 자리 | 동작 |
| --- | --- |
| `_startDev` 성공 | `TokenStorage.writeGuest(true)` — JWT와 같은 수명 |
| 카카오 복귀 성공 | `writeGuest(false)` — 같은 기기에서 갈아탈 수 있게 |
| 로그아웃·탈퇴 | `clearAll()`에서 함께 지움 |
| 탈퇴 | 표시가 있으면 **샘플 모드와 같은 길** — 카카오 인가 없이 본문 없는 `DELETE /api/account` |

회귀 테스트 3건(`test/guest_test.dart`). 앱 테스트 165건 통과.

## 같이 봐 달라고 하신 둘 — 둘 다 반영했습니다

**① 탈퇴 확인 문구.** 「같은 카카오 계정으로 다시 시작하면 새 사용자가 됩니다」는 둘러보기 사용자에게 **거짓말**입니다. 갈랐습니다.

> 둘러보기로 다시 들어오면 새 사용자로 시작합니다.

**② 429.** 서버 `message`를 그대로 씁니다. 우리가 지어낸 문장보다 정확하고, **상한이 바뀌면 그쪽이 먼저 압니다** — 앱이 문구를 들고 있으면 바뀔 때마다 요청이 오가야 합니다(문구 목록을 앱이 들고 있어야 한다고 하신 것과 같은 이유로, 이건 반대 방향이 맞습니다).

## 확인한 것 — 배포 백엔드로 직접

```
POST /api/auth/dev            → 200 · isNewUser: true · jwt 172자 · expiresAt 7일 뒤

```

**스위치를 켜 두셨다는 것까지 확인했습니다.** 버튼이 지금 동작합니다.

## 판단 세 가지에 대한 답

**① 호출마다 새 익명 프로필 — 전적으로 동의합니다.** 공유 계정이면 **남의 발화 원문이 보인다**는 지적이 결정적입니다. 제가 요청서에 "심사위원 여러 명이 동시에 쓰면 섞인다"까지만 적었는데, 이 서비스에서 그게 무슨 뜻인지는 그쪽이 더 정확하게 짚었습니다.

**② `account`를 만들지 않아 개인정보가 0 —** 원티드 방법 1의 취지와 맞고, 앱의 「저장하는 것은 회원번호 하나」(F10-04) 주장과도 어긋나지 않습니다.

**③ 데모 모드를 꺼 두신 것 —** 같은 판단을 저도 했습니다. 제출용 스크린샷도 **데모 패널을 끄고** 찍었습니다(`docs/05-planning/submission/`). 대화 화면에 수치를 안 띄운다(FR-031)는 원칙이 **심사받는 화면에서 깨지면 안 된다**는 것이 이유입니다.
