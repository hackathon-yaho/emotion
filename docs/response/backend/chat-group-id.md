## 1. 받습니까 → **받습니다. 소켓이 열린 직후입니다**

Hume은 연결 직후 **`chat_metadata`** 프레임을 한 번 보냅니다.

```json
{ "type": "chat_metadata", "chat_group_id": "cg_...", "chat_id": "chat_..." }
```

- **첫 응답 메타가 아니라 소켓 이벤트**입니다. 사용자가 한 마디도 하기 전에 옵니다
- 앱은 이걸 `EviConnected`로 올려 받고 있습니다. 테스트로 못 박아 뒀습니다

## 2·3. **3안(연결 직후 전송)으로 부탁드립니다**

물어보신 결정 근거가 "앱에서 어느 시점에 값이 손에 들어오는지"였는데, **연결 직후**입니다. 그러면 3안이 2안의 상위집합이 됩니다.

- **강제 종료를 덮는 것이 3안뿐입니다.** 지적하신 그대로 — `end`로 보내면 강제 종료 때 못 받는데, **이어하기가 필요한 상황이 정확히 그 상황**입니다. 값이 이미 손에 있으니 `end`까지 기다릴 이유가 없습니다
- **2안(`end`에 필드 추가)은 안 해도 됩니다.** 두 경로를 다 두면 같은 값을 두 번 쓰게 되고, 어느 쪽이 최신인지 판단하는 코드가 생깁니다

제안하는 모양입니다 — 필요하신 대로 고쳐 주십시오.

```
POST /api/session/{sessionId}/chat-group
{ "chatGroupId": "cg_2b7f11" }
→ 204
```

| 항목 | 제안 |
| --- | --- |
| 호출 시점 | `chat_metadata` 수신 직후 **한 번** |
| 실패 처리 | **앱이 재시도하지 않습니다.** 실패하면 그 세션만 맥락 복원이 안 되고, 대화는 그대로 진행됩니다 — 대화 중에 재시도 루프를 돌릴 이유가 없습니다 |
| 같은 값 재전송 | 이어하기로 재연결하면 **같은 `chat_group_id`가 다시 옵니다.** 멱등으로 처리해 주시면 앱이 판단할 게 없습니다 |
| 세션 상태 | 이미 `ended`면 **거절하셔도 됩니다.** 앱은 응답을 보지 않습니다 |

## 지금 앱 상태

**값은 받고 있고, 백엔드로 보내는 코드만 없습니다.** 엔드포인트가 계약에 올라오면 `chatGroupIdProvider`에서 바로 호출합니다 — 자리는 만들어 뒀고 주석에 이 문서를 걸어 뒀습니다.

그동안은 **같은 세션 안에서 재연결할 때만** 쓰입니다. 앱을 완전히 닫으면 값이 사라지므로, 그 경우가 지금 맥락이 복원되지 않는 유일한 구간입니다.

## 한 가지 더 — 이어하기 응답의 `resumedChatGroupId`가 지금 빈 문자열입니다

계약 §2-5-1은 이 필드를 **필수(non-null)** 로 적어 뒤, 값이 없을 때 무엇을 주는지는 안 적혀 있습니다. 백엔드 구현이 컬럼을 그대로 내려 항상 `null`이라고 하셨는데, **필수 필드에 `null`이 오면 앱 파서가 깨집니다.**

앱은 지금 **빈 문자열도 "없음"으로 취급**해 방어해 두었습니다. 다만 계약 쪽에서 한 줄 정해 주시면 좋겠습니다 — **`null` 허용으로 적으시거나(§1-3의 null 규칙과 결이 맞습니다), 없으면 빈 문자열로 고정**하시거나요. 어느 쪽이든 앱은 맞추겠습니다.
