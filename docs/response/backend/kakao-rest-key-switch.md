# 회신 — `KAKAO_REST_KEY`로 확정. 앱 코드·워크플로 다 바꿨습니다

- 원본 요청: [`../../request/app/kakao-rest-key-switch.md`](../../request/app/kakao-rest-key-switch.md) (백엔드 → 앱, 2026-09-05)
- 회신자: 앱
- 회신일: 2026-09-05

---

## 1. 변수명 — **`KAKAO_REST_KEY`** 로 갑니다

이름 그대로 쓰겠습니다. **앱 쪽은 이미 다 바꿨습니다** — 등록만 해 주시면 다음 배포에서 들어갑니다.

| 자리 | 값 |
| --- | --- |
| repo variable | `KAKAO_REST_KEY` (백엔드가 등록) |
| 워크플로 | `app-web.yml`의 `--dart-define=KAKAO_REST_KEY=${{ vars.KAKAO_REST_KEY }}` |
| 앱 코드 | `core/config/env.dart`의 `Env.kakaoRestKey` |

**REST 키가 번들에 들어가는 것이 정상이라는 설명, 그대로 코드 주석에 옮겨 뒀습니다** — 인가 URL에 실리는 값이라 어차피 주소창에 보이고, 보호는 서버의 클라이언트 시크릿과 Redirect URI 화이트리스트가 한다는 것까지요. **Hume 키를 앱에 두지 않는 것(FR-013)과 성격이 다른 값**이라는 구분이 코드에 없으면, 나중에 누가 "키가 번들에 있다"만 보고 FR-013 위반으로 오해합니다.

## 2. 값 전달 경로 — 사설 채널이면 됩니다. 다만 **앱에는 REST 키만** 주세요

- **repo variable은 팀장님이 직접 등록**해 주시면 저에게 값이 올 필요조차 없습니다. 배포 빌드는 그것만 있으면 됩니다
- **로컬 개발용 값만** 사설 채널(카카오톡 DM 등)로 주시면 됩니다. `--dart-define`으로만 쓰고 저장소·문서·대화에 남기지 않습니다
- **`INTERNAL_SHARED_SECRET`은 앱에 주지 마세요.** 앱↔백엔드 인증은 JWT 하나이고(§1-1), 그 값은 AI서버↔백엔드 내부 인증입니다. 웹 번들에 들어가는 순간 **누구나 내부 엔드포인트를 부를 수 있게 됩니다.** 경로를 하나로 정하는 것은 좋은데, **받는 사람이 다르다는 것만 지켜 주십시오**

## 3. `unlink` 결정에 동의합니다

**리프레시 토큰을 보관하지 않는 쪽**이 맞습니다. 제가 두 안을 올렸을 때는 "탈퇴하려는 사람에게 재로그인"이 부담이라고 봤는데, 근거로 드신 것이 더 무겁습니다 — **2개월짜리 카카오 자격증명을 전 사용자분 몫으로 DB가 들고 있는 상태**는 "저장하는 것은 회원번호 하나"(PRD §5.1 · S00 고지)와 같은 줄에 세울 수 없습니다. 음성 원본을 안 받는 것, 동의항목을 회원번호만 연 것과 같은 판단이라는 지적 그대로입니다.

`unlink`가 사용자 액세스 토큰으로 된다는 것도 확인해 주셔서 담당이 정리됐습니다 — **어드민 키 없이 백엔드가 끊습니다.**

**동의 화면이 매번 뜨는지는 붙여보고 알려드리겠습니다.** F10-03은 Phase 6이라 그때 실측하겠습니다.

## 4. 지금 상태 — 값이 오면 바로 붙습니다

**로그인 구현이 남은 이유는 키뿐입니다.** 흐름·계약·경로 전부 확정입니다.

```
① S00 "카카오로 시작하기" → 인가 URL로 페이지 이동
   https://kauth.kakao.com/oauth/authorize
     ?client_id={KAKAO_REST_KEY}&redirect_uri={등록된 주소}&response_type=code
② 동의 → 등록된 Redirect URI로 복귀 (?code=...)
③ 앱 시작 시 Uri.base의 code를 읽어 POST /api/auth/kakao
④ JWT 저장 → 게이트 통과 → 홈
⑤ 주소창의 ?code= 를 지운다 (history.replaceState)
```

⑤는 말씀대로 앱만 할 수 있는 일이라 저희가 합니다.

**참고로 지금은 로그인 없이도 화면 전체를 볼 수 있습니다** — 주소에 `?sample=1`을 붙이면 백엔드·Hume을 타지 않고 준비된 데이터로 11개 화면이 다 그려집니다(`app/README.md`「데이터는 어디서 오나」). 백엔드 붙이기 전에 화면을 확인하실 때 쓰시면 됩니다.
