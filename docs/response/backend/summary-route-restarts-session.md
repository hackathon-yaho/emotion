- 원본 요청: [`../../request/app/summary-route-restarts-session.md`](../../request/app/summary-route-restarts-session.md) (백엔드 → 앱, 2026-09-14 · 09-15 개정)

## 결론 — 짚어주신 원인이 정확합니다. ①대로 고쳤습니다

```dart
// 전: static const summary = '/conversation/summary';   ← 대화의 자식
// 후: static const summary = '/summary';                 ← 최상위
```

`go_router`가 자식 라우트로 갈 때 **부모 페이지를 함께 만든다**는 것, 그 페이지가 `push`로 연 원래 페이지와 **키가 달라 새로 만들어진다**는 것까지 소스 줄번호로 짚어주신 그대로였습니다.

## 검증 — 제시하신 기준 그대로

**「대화를 끝낸 뒤 `POST /api/session/start`가 나가지 않는다」** 를 소켓 연결 수로 쟀습니다(가짜 EVI 서버가 연결마다 한 줄 남깁니다 — 세션이 열리면 소켓도 열립니다).

| | 소켓 연결 |
| --- | --- |
| 고치기 전 | **2회** ← 두 번째가 빈 세션 |
| 고친 뒤 | **1회** |

요약 화면도 정상입니다(`3분 34초 · 12턴`). 주소가 `#/summary`로 바뀌었습니다.

**구조를 테스트로 잠갔습니다** — `test/routes_test.dart`가 「요약은 대화의 자식이 아니다」를 단언합니다. 다시 중첩되면 거기서 깨집니다. 앱 테스트 142건 통과.

## 지적해주신 커밋 세 건에 대한 답

- **`0fe0e10` 종료 재시도** — *"종료가 실패해 남은 대화는 없다"*는 실측을 받아들입니다. **제가 원인을 잘못 짚었습니다.** 다만 재시도는 남겨 둡니다 — 해롭지 않고, 실제로 실패할 때 조용히 삼키던 것은 그 자체로 결함이었습니다.
- **`da7ff90` ② 인사말 재생** — (a)만 막는다는 지적이 맞습니다. **(b)는 이 라우트 수정으로 사라집니다** — 숨은 화면이 아예 생기지 않으니 새 연결도, 그 인사도 없습니다.
- **`3d9c1a7` 요약이 지워질 것** — **일어나기 전에 막혔습니다.** 숨은 화면이 없으니 `_enter()`가 다시 돌지 않습니다. 짚어주지 않았으면 다음 테스트에서 「방금 끝낸 대화가 없습니다」를 보고 또 엉뚱한 곳을 팠을 겁니다.

## ③ 「새로고침하면 사라졌다」 — 카드의 id는 **끝낸 세션과 달랐습니다**

앱에 진단을 넣어(`?debug=1`) 카드에 **`· 카드 xxxxxxxx · 끝낸 것 xxxxxxxx`** 를 나란히 찍게 했고, 테스트에서 **둘이 다른 값**으로 확인됐습니다(카드 `52e430a2`). 요약 화면에는 종료 실패 문구가 없었습니다 — **종료는 성공했고 카드는 그 뒤에 생긴 빈 세션**이라는 뜻입니다.

그러므로 `endedSessionIdProvider` 필터는 **이 증상을 가린 적이 없습니다.** 말씀대로입니다. 필터 자체는 남겨 둡니다(끝낸 세션이 잠깐 열려 보이는 경우를 위한 것이고, v1.12가 배포되면 역할이 겹칩니다).

「새로고침하면 사라졌다」는 **제가 09-14에 다른 증상(소켓 끊김으로 끝난 대화)과 섞어 보고한 것**으로 보입니다. 지금 근거로는 그 관찰을 유지할 수 없습니다 — 거둡니다.

## 감사합니다 — 그리고 정정

**「비용 영향은 작다」가 아니라 26%였다**는 실측, 그리고 **요약 화면에 머무는 동안 마이크가 열려 있었다**는 확인이 이 건의 무게를 바꿨습니다. 09-06에 뒤로 가기에서 같은 일을 잡으며 *"요금보다 이쪽이 더 무겁다"*고 적어 놓고, 정작 같은 결함을 요약 경로에서 놓쳤습니다.

**제가 사흘 동안 증상만 쫓고 있었습니다** — 종료 재시도, 가림막, 요약 비우기 셋 다 이 원인 위에서는 헛수고였습니다. DB와 Hume 기록을 맞춰 원인을 특정해 주신 덕에 끝났습니다.
