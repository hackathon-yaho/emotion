## 배경 — 원티드 안내

원티드가 참가팀에 **투표자·심사위원이 로그인 없이 핵심 기능을 써 볼 수 있게** 해 달라고 안내했습니다(심사·투표 **9/21~10/5**). 방법은 셋이었습니다.

| 방법 | 내용 | 우리 선택 |
| --- | --- | --- |
| **1-A 한시적 개방** | 실서비스에 로그인 없는 경로를 연다 | **✅ 이것** — 앱 버튼이 이미 이 형태로 배포돼 있다 |
| 1-B 별도 데모 버전 | 다른 URL로 데모를 따로 만든다 | 배포본을 하나 더 운영할 이유가 없다(결제 로직도 없다) |
| 2 테스트 계정 제공 | 개인정보 없는 계정을 제출서에 적는다 | 1-A가 되므로 불필요 |
| 3 방침·약관 게재 | 투표자 개인정보 책임을 팀이 진다 | 해당 없음 — **투표자에게서 개인정보를 받지 않는다** |

**제출 URL은 지금 주소(`https://hackathon-yaho.github.io/emotion/`) 그대로입니다.**

## 판단을 맡기신 세 가지

### ① 어느 계정으로 — **호출마다 새 익명 프로필**

말씀하신 대로 한 계정을 공유하면 서로의 대화가 섞여 보입니다. 이 서비스에서는 그게 **남의 발화 원문이 보인다**는 뜻이라 공유 계정은 택하지 않았습니다. 패턴 관찰(F7)도 여러 사람 데이터로 판정하게 되고, 누가 탈퇴를 누르면 모두의 기록이 한꺼번에 지워집니다.

- **`account`를 만들지 않습니다** — `profile` + `user_baseline`만 만듭니다. 카카오 식별자가 없으니 **개인정보가 하나도 없습니다**(원티드 방법 1의 취지와 맞습니다)
- `isNewUser`는 **항상 `true`** — 온보딩 고지가 정상적으로 뜹니다
- 같은 브라우저는 받은 JWT(7일)로 같은 프로필을 계속 씁니다. **다시 누르면 다른 프로필**이 되고 이전 기록으로 돌아가는 경로는 없습니다
- **데모 모드는 꺼져 있습니다.** 투표자는 실제 사용자와 같은 화면을 봅니다 — 대화 화면에 수치를 안 띄운다(FR-031)는 제품 원칙이 심사받는 화면에서 깨지면 안 된다고 봤습니다

### ② 막을 장치 — **스위치 + 서버 전체 분당 30회**

| 장치 | 내용 |
| --- | --- |
| **`DEV_LOGIN_ENABLED`** | 기본 `false` → **404**. 앱이 이미 404를 「둘러보기는 아직 준비되지 않았습니다」로 보여주니 끈 상태도 고장으로 안 보입니다 |
| **분당 30회** | **서버 전체** 기준. 넘으면 **429 `TOO_MANY_REQUESTS`**(§1-2 신설). IP별로 세지 않는 이유는 프록시 뒤라 `X-Forwarded-For`를 믿어야 해서입니다 |

⚠️ 한계 — 누가 일부러 분당 30회를 계속 두드리면 진짜 투표자도 막힙니다. 심사 기간 한정이라 감수했습니다.

로그인 경로 자체는 빈 행 몇 개라 쌉니다. **비싼 건 그 뒤의 음성 대화(Hume 분·동시 접속)** 입니다 — 코드로 막지 않고 **Hume 계정 쪽에서 상한을 거는 것**으로 정했고, AI에 확인을 요청했습니다(`../../request/ai/hume-usage-for-voting.md`). 투표자가 몰리면 동시 접속 상한에 걸리므로 **대기열(`SESSION_QUEUE_ENABLED`, §2-14)을 같이 켭니다.** 앱은 202 처리를 9/6에 이미 붙였습니다(`../../response/backend/session-queue.md`). 정원을 Hume 플랜의 동시 접속 수에 맞춰야 해서 **AI 회신(③) 뒤에 켜고, 켤 때 말씀하신 두 가지(202 → 폴링 → 입장 · 줄이 있을 때 신규도 202)를 같이 확인하겠습니다.**

### ③ 탈퇴(§2-3) — **서버는 문제없습니다. 앱 흐름에 걸리는 게 하나 있습니다**

- 서버: `deleteAllFor`가 `account_profile`에서 연결 계정을 찾아 지우는데, 둘러보기 프로필은 연결이 없으니 그 단계만 건너뛰고 나머지는 그대로 지웁니다. 본문 없이 오면 unlink도 건너뜁니다. **테스트로 확인했습니다**
- 앱: 설정 화면의 탈퇴가 **샘플 모드가 아니면 항상 카카오 인가로 보냅니다**(`settings_screen.dart` 222행 부근). 카카오 계정이 없는 투표자는 거기서 막히고, 계정이 있는 투표자는 **자기 카카오 계정을 둘러보기 프로필에 대고 인가**하게 됩니다 → `../../request/app/guest-withdraw.md`

## 닫는 날과 파기

원티드 일정: 심사·투표 9/21~10/5 → **TOP20 발표 10/7** → 데모데이 10/17.

| 10/7 결과 | 끄고 파기하는 날 |
| --- | --- |
| TOP20 탈락 | **10/7** |
| TOP20 진출 | **10/18** (데모데이 다음 날) |

**절차** — ① Render에서 `DEV_LOGIN_ENABLED=false` → ② `POST /internal/dev-profiles/purge`(`X-Internal-Secret`) → `{"deleted": n}` ③ 파기가 끝나면 `DevLoginController`와 계약 §2-1-1을 지운다.

- 파기는 **탈퇴와 같은 삭제 경로**(`deleteAllFor`)를 프로필마다 부릅니다. 삭제 로직을 두 곳에 두지 않았습니다
- **스위치가 켜진 채로 부르면 403으로 거절합니다** — 둘러보는 중인 사람의 기록이 대화 도중에 사라지기 때문입니다
- 지우는 대상은 **`account_profile` 연결이 없는 프로필**입니다. 운영 DB에 오늘(9/18) 그런 프로필은 **0개**입니다(전체 3개, 전부 카카오 연결) — 둘러보기가 아닌 프로필이 섞여 지워질 일은 없습니다

원티드 안내에서 "대회 종료 후 파기"는 방법 3에 붙은 조건이지만, 투표자의 발화 원문이 남는 건 우리 원칙(FR-003)과도 맞지 않아 똑같이 지웁니다.

## 앱이 할 일

- **둘러보기 버튼: 없음.** 응답 모양이 §2-1과 같습니다
- **429 문구 (선택)**: 지금은 「로그인이 완료되지 않았습니다. 다시 시도해 주세요.」로 뜹니다. 틀린 말은 아니라 그대로 둬도 됩니다. 바꾸려면 `code == TOO_MANY_REQUESTS`로 분기하고 서버 `message`(「지금 요청이 많습니다. 잠시 후 다시 시도해 주세요.」)를 그대로 쓰면 됩니다
