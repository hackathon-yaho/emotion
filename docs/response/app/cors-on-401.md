## 결론 — 결함이 맞고, 짚어주신 단서도 정확했습니다

배포본에서 그대로 재현했습니다. **200·400에는 붙는데 필터가 만드는 401에는 한 줄도 없었습니다.**

**"400은 컨트롤러가 만들고 401은 인증 필터가 컨트롤러 앞에서 만든다"는 짐작이 원인 그 자체였습니다.**

`CorsConfig`가 `WebMvcConfigurer`로 돼 있었습니다. 그건 **MVC 계층의 CORS**라 요청이 `DispatcherServlet`까지 가야 헤더가 붙습니다. `JwtAuthFilter`는 그보다 앞에서 401을 만들고 끝내므로 **CORS 처리를 아예 안 탑니다.**

## 고친 방법

`CorsFilter`를 `HIGHEST_PRECEDENCE`로 등록해 **인증 필터보다 앞**에 뒀습니다. 허용 오리진·메서드·헤더 설정값은 그대로입니다.

- 인증 필터들은 `@Component` 기본 등록이라 `LOWEST_PRECEDENCE`입니다. 그래서 이 값이어야 먼저 돕니다
- **필터마다 손으로 헤더를 붙이지 않았습니다.** 그러면 다음에 필터가 하나 늘 때 또 빠집니다. 모든 응답에 붙어야 하는 헤더는 **모든 응답이 지나가는 자리**에서 붙입니다

## 검증 — 주신 `curl` 그대로

```
access-control-allow-origin: https://hackathon-yaho.github.io
```

| 요청 | 상태 | `access-control-allow-origin` |
| --- | --- | --- |
| `GET /api/health` | 200 | ✅ |
| `POST /api/auth/kakao` (빈 본문) | 400 | ✅ |
| **`GET /api/me` (잘못된 JWT)** | **401** | ✅ **붙습니다** |
| **`GET /api/me` (Authorization 없음)** | **401** | ✅ |
| `GET /api/nope` (없는 경로) | 401 | ✅ |
| `GET /internal/sessions/{id}` (시크릿 없음) | 401 | ✅ |

**만료 토큰(`TOKEN_EXPIRED`)은 배포본에서 직접 재현하지 않았습니다** — 실제 만료 토큰을 만들려면 배포용 `JWT_SECRET`으로 서명해야 해서입니다. 다만 **잘못된 JWT와 완전히 같은 경로**(`JwtAuthFilter`의 같은 `reject()`)를 타고, 그 경로는 위 3번째 행으로 확인됐습니다. 만료 토큰 쪽은 **회귀 테스트로 따로 고정**했습니다(아래).

## 403·404·500에 대한 답

**이제 계층과 무관합니다.** CORS 필터가 가장 앞에서 돌므로 **그 뒤에서 무엇이 어떤 응답을 만들든** 헤더가 붙습니다. 필터가 만든 401도, 컨트롤러가 만든 403도, 예외 핸들러가 만든 500도 같습니다.

**다만 상태 코드 자체는 지금 이렇게 나옵니다** — 앱이 분기를 짤 때 참고하실 것이 있습니다.

- **404는 미인증 상태에서 나오지 않습니다.** 인증 필터가 `/api/**` 전체를 가로채므로 **없는 경로도 401**입니다. 인증을 통과한 뒤에야 404가 보입니다
- **§2-11·§2-12의 403(타 사용자 세션)은 컨트롤러가 만듭니다.** 원래도 MVC 계층을 지나서 헤더가 붙고 있었고, 지금은 필터에서 한 번 더 확실해졌습니다. **그쪽은 손볼 곳이 없습니다**

## 테스트 — 프리플라이트만으로는 못 잡습니다

회귀 테스트 2건을 넣었습니다(**107건 통과**).

- 인증 필터가 만든 401에 헤더가 붙는가
- **만료 토큰의 401**에 붙는가 — F1-02가 실제로 보는 응답이라 따로 봅니다

**기존 프리플라이트 테스트 3건은 전부 통과하는 채로 이 결함이 배포돼 있었습니다.** 프리플라이트(`OPTIONS`)는 인증 필터가 메서드로 제외하고 있어 MVC까지 가는데, **본 요청의 401은 그 앞에서 끝나기 때문**입니다. 같은 "CORS 테스트"인데 서로 다른 경로를 봅니다 — 그래서 401 쪽을 따로 넣었습니다.

## 함께 알려드립니다

- **콜드 스타트 대응 감사합니다.** 타임아웃 상향과 **GET에만 재시도**(POST는 세션이 둘 생기니 안 한다)는 정확한 판단입니다. **cron 킵얼라이브는 아직 등록 전**입니다 — `cron-job.org`로 정했고 팀장이 겁니다. 실측 **274초**를 보셨다는 건 그 전까지 못 덮는 구간이 실재한다는 뜻이라, 등록을 앞당기도록 하겠습니다
- **AI서버가 배포됐습니다** — `https://emotion-ai-server-gq7yhdrrlq-du.a.run.app`. 백엔드의 `AI_SERVER_BASE_URL`도 넣었습니다. 다만 **AI서버 쪽 공유 시크릿이 아직 배포용으로 안 바뀌어** 세션 조회가 401로 떨어지는 상태라, **대화는 그게 맞춰진 뒤에 성립합니다**
- 오늘 잡으신 앱 결함 4건 중 **`resumedChatGroupId: null`에 파서가 죽던 것** — 계약 §1-3에서 null을 명시한 필드라 서버는 그대로 내보냅니다. 고치신 방향이 맞습니다
