## 결론

**제안하신 형태를 거의 그대로 채택했습니다.** 다섯 항목 모두 앱 제안대로 갔고, 다른 곳은 상위 개수(7개로 확정)뿐입니다.

| 결정 요청 | 답 |
| --- | --- |
| 1. `GET /api/trend` 확장 vs 신규 엔드포인트 | **`GET /api/trend` 확장.** S04가 이미 하는 호출이라 왕복이 늘지 않습니다 |
| 2. 필드명 | **`tagGaps`·`userAvgGap`** — 제안하신 이름 그대로 |
| 3. 개수 | **상위 7개**, `tagAvgGap` 내림차순 |
| 4. `range` 종속 여부 | **종속됩니다.** 같은 화면의 두 선 그래프와 기간이 달라지면 안 된다는 판단에 동의합니다 |
| 5. 3회 미만 필터 | **서버가 합니다.** F7-03과 같은 기준이 한 곳에만 남습니다 |

## 응답 (계약 §2-8, v1.4)

```json
{
  "range": "30d",
  "timezone": "Asia/Seoul",
  "points": [ ... ],
  "highlights": [ ... ],
  "userAvgGap": 0.72,
  "tagGaps": [
    { "tag": "회의", "occurrences": 7, "tagAvgGap": 1.31 },
    { "tag": "야근", "occurrences": 4, "tagAvgGap": 0.98 },
    { "tag": "가족", "occurrences": 3, "tagAvgGap": 0.65 }
  ]
}
```

- `userAvgGap`은 **전 기간** 평균입니다(`range`에 종속되지 않습니다). 개인 baseline과 같은 값이어야 관찰의 `evidence.userAvgGap`과 어긋나지 않기 때문입니다 — 판정선 `×1.5`는 앱이 이 값으로 그립니다
- `tagGaps`는 **`range`에 종속**됩니다. 두 값의 기간이 다른 것은 의도된 것입니다: 기준선은 "나라는 사람의 평균", 막대는 "이 기간의 이야기들"입니다
- 3회 이상인 태그가 없으면 `tagGaps: []`, `userAvgGap`은 그대로 내려갑니다. 갭이 한 건도 없으면 `userAvgGap`은 `null`입니다(§1-3 — 측정하지 못했다는 뜻)

## 상위 7개로 정한 이유

화면이 5~7개가 읽기 좋다고 하셨고, **막대가 몇 개 없을 때 잘리지 않는 쪽**을 택했습니다. 도그푸딩 10일 × 3분 대화면 3회 이상 태그가 7개를 넘기기 쉽지 않아, 실질적으로는 "있는 것을 다 보여주는" 값입니다.

## 새 계산이 아니라는 지적이 맞습니다

F7-02 태그별 집계가 배치에서 이미 같은 숫자를 구합니다. 다만 **배치는 관찰을 만들 때만 돌고 결과를 저장하지 않으므로**(판정을 통과한 것만 `observation`에 남습니다), `GET /api/trend`는 같은 집계를 조회 시점에 다시 수행합니다. 도그푸딩 규모(3인 × 수백 턴)에서 밀리초 단위라 캐시를 두지 않았습니다.

## 함께 고친 것

요청 문서 끝에 알려주신 두 가지, 확인했습니다.

- **spec 총괄표 F1-04·F10-03 담당 `A` → `A/C`** — 반영돼 있는 것을 확인했습니다. 감사합니다
- **페이징** — 계약 §1-4대로면 맞습니다

그리고 이 요청을 처리하며 **F9-02(갭 구간 강조)에서 별건이 하나 나왔습니다.**

계약 §2-8의 `highlights`는 "갭이 임계를 넘은 연속 구간"인데, **그 임계값이 DB 어디에도 저장되지 않고 있었습니다.** 지금은 `.env` 값이고 PRD §14-5로 **반드시 한 번 바뀝니다** — 바꾸는 순간 과거 날짜의 음영이 전부 재판정되어, 그날 실제로 되물었던 근거와 화면이 어긋납니다.

그래서 `voice_session.gap_threshold`(세션 시작 시 적용값 스냅샷)를 신설하고, `highlights`는 그 값으로 판정하도록 계약 §2-8과 spec F9-02·§6-1을 고쳤습니다. **앱이 할 일은 없습니다** — 응답 형태는 그대로입니다.

덤으로 **spec 총괄표의 F9-02 담당을 `C` → `A/C`로 고쳤습니다.** `highlights`를 서버가 계산해 내려주는데 담당에 백엔드가 없었습니다.
