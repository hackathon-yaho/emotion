# 회신 — 「생각 중」 넣었습니다. 기준은 **4초**입니다

- 원본 요청: [`../../request/app/conversation-latency.md`](../../request/app/conversation-latency.md) (AI → 앱, 2026-09-05)
- 회신자: 앱
- 회신일: 2026-09-06

---

## 1. 「생각 중」 상태 — **넣었습니다**

`TalkState.thinking`을 추가했고, **EVI가 `user_message`를 주는 시점**(전사 확정)부터 **`assistant_message`가 오는 시점**까지입니다. 지적하신 구간과 정확히 같습니다.

- 라벨은 **"생각하고 있습니다"** — 화면 문구는 "-습니다"로 통일돼 있습니다(design-system §7 결정 23)
- 사용자 발화를 3초간 띄우던 것(§6-1 절충안)과 **같이 뜹니다** — 방금 한 말이 보이면서 링이 생각에 들어가는 모양입니다

## 2. 정상·이상의 경계 — **4초**

| 구간 | 화면 |
| --- | --- |
| 0 ~ 4초 | 링만 움직입니다. **문구를 더 붙이지 않습니다** |
| 4초 초과 | 한 줄 추가 — **"조금 오래 걸리고 있습니다"** |

**4초로 잡은 이유는 실측 p95가 3.2초이기 때문입니다.** 정상 범위 안에서 문구가 뜨면 **매 턴 사과하는 화면**이 됩니다. p95 위에서만 뜨면 스무 턴에 한 번 정도인데, 그 정도면 "가끔 오래 걸린다"는 사실을 정직하게 전달하는 빈도라고 봅니다.

**타임아웃은 따로 두지 않았습니다.** 응답이 영영 안 오는 경우는 소켓이 오류나 종료로 알려주고(EVI `error` 프레임·연결 끊김), 그건 이미 F2-04 경로로 화면 문구가 갈립니다. 앱이 임의로 "N초 넘으면 실패"를 정하면 **실제로는 오고 있는 응답을 끊는** 쪽이 더 위험합니다.

**측정값이 바뀌면 이 숫자도 바뀝니다.** 유료 티어로 올리거나 모델을 바꿔 p95가 내려가면 알려주세요 — 상수 하나입니다(`_slowAfter`).

## 3. 두 링으로 표현 가능한가 — **가능하고, 그렇게 했습니다**

**별도 표시(점 세 개·스피너)를 두지 않았습니다.** 이 화면의 유일한 그림이 두 링이고, 거기에 로딩 기호를 얹으면 「밤의 활자」가 깨집니다.

| 상태 | 링 |
| --- | --- |
| 듣는 중 | 지름 200 · 간격 8 |
| **생각 중** | 지름 188 · 간격 4 — **조금 작고 가깝습니다.** 밖으로 열려 있던 것이 안으로 모이는 모양입니다 |
| 말하는 중 | 지름 168 · 간격 3 |

여기에 **1.6초 주기의 느린 숨**을 넣었습니다(지름 ±6, 간격 ±3, 투명도 −0.14). 깜빡임이 아니라 숨이라 조용합니다.

- **색은 건드리지 않았습니다** — 감정에 따라 색이 변하면 사용자가 "화면이 어두워졌네"로 읽어 사실상 갭 노출이 됩니다(FR-030)
- **생각 중일 때만 애니메이션이 돕니다.** 계속 돌리면 웹에서 매 프레임을 다시 그립니다

## 측정값 정정, 잘 보았습니다

처음 올리신 12.5초를 그대로 믿고 화면을 설계했다면 **"오래 걸림"이 기본 상태인 화면**을 만들었을 겁니다. 연속 호출로 무료 티어 한도를 스스로 유발했다는 것까지 적어 주셔서, 4초라는 경계를 p95 위에 놓는 판단을 할 수 있었습니다.

**NFR-01(p95 2초)을 넘는 것 자체**는 팀 결정이라 제가 답할 자리가 아닙니다. 다만 화면 쪽에서는 **3.2초를 감당할 수 있게** 됐다는 것만 말씀드립니다.
