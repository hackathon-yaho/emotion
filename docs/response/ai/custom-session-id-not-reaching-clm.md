# 회신 — `session_settings`에 실었습니다. 대화가 돕니다

- 원본 요청: [`../../request/app/custom-session-id-not-reaching-clm.md`](../../request/app/custom-session-id-not-reaching-clm.md) (AI → 앱, 2026-09-07)
- 회신자: 앱
- 회신일: 2026-09-07

---

## 결론

**고쳤고 배포됐습니다.** 짚어주신 그대로 `session_settings`에 한 줄 얹었습니다.

```dart
_send({
  'type': 'session_settings',
  'custom_session_id': sessionId,   // ← 여기
  'audio': {'encoding': 'linear16', 'sample_rate': 16000, 'channels': 1},
});
```

- 커밋 `48a0a86` · 배포본 확인: `main.dart.js`에 `custom_session_id` **2건**(쿼리 1 + `session_settings` 1)
- **1.5초 끊김은 사라졌습니다.** 소켓이 붙고, 사용자가 말하고, **AI가 첫 대답을 합니다**

**소켓 URL의 쿼리는 남겼습니다.** 지우는 것이 깔끔하다는 말씀에 동의하지만, 둘 다 보내는 것이 해롭지 않고 **Hume이 어느 쪽을 읽는지에 우리 대화가 걸리지 않게** 하고 싶었습니다. 계약 v1.10 정정 확인했습니다.

## 원인 판정에 대해

**계약서가 틀렸다는 판정에 이견 없습니다.** 다만 앱 쪽 몫도 있었습니다 — 코드 주석에 *"예제에 없어 우리가 추가합니다"* 라고 적어 두고 **그 값이 실제로 CLM에 닿는지 확인하지 않았습니다.** 계약서를 근거로 들었지만, 확인하지 않은 것은 앱입니다.

401을 로그에 남기도록 고쳐 배포해 주신 것이 결정적이었습니다. 그 세 줄 구분이 없었으면 앱은 `closed 1000`(정상 종료)만 보고 있었을 겁니다 — 화면에는 원인이 통째로 안 보였습니다.

## 이어서 — 지금은 다음 문제로 넘어가 있습니다

**첫 대답은 정상인데, 두 번째 턴부터 계속 `FALLBACK`이 나옵니다.**

> 지금은 제가 잘 듣지 못했어요. 한 번만 다시 말씀해 주시겠어요?

별도 요청으로 올렸습니다 — [`../../request/ai/respond-fallback.md`](../../request/ai/respond-fallback.md). **로그의 태그 하나면 갈립니다**: `respond_failed`(예외·429 계열)인지 `respond_bad_request`(요청 거절)인지.

앱 쪽은 이렇게 배제해 두었습니다.

| 확인한 것 | 결과 |
| --- | --- |
| 나가는 오디오 형식 | 717,464B / 22.4초 = **16k 모노 PCM16과 일치** (가짜 EVI 서버로 수신해 측정) |
| 무음 여부 | RMS 평균 **1013** · 최대 **10711** — 무음이 아님 |
| 턴 2부터 앱이 달리하는 것 | **없음.** 소켓 1회, `session_settings` 1회, 이후 `audio_input`만. CLM 요청은 Hume이 만듭니다 |

화면에도 진단 한 줄을 띄웠습니다(`SHOW_ERROR_DETAIL` 빌드) — `마이크 N (최대 N) · AI 발화 · 조각 · 끼어들기`. 실사용에서 **말할 때 마이크 값이 올라가는 것**을 확인했습니다.

## 곁다리 — `GET /` 404는 앱이 아닙니다

**앱 번들 어디에도 AI서버 주소가 없습니다** (`run.app`·`emotion-ai-server` grep 0건). 앱은 백엔드만 부르고, AI서버는 Hume이 부릅니다. 킵얼라이브나 외부 스캐너 쪽으로 보입니다.
