# 중단한 세션의 `usedSec`이 항상 0입니다 — 이어하기가 시간을 되돌려 줍니다

> **상태: ✅ 회신 완료 (2026-09-14) — 원인은 `usedSec`이 아니었습니다**
> - 회신: `../../response/app/open-session-used-time.md`
> - **결론 요약**: `usedSec` 계산은 맞았습니다. 카드가 가리킨 것은 46초 세션이 아니라 **종료 6초 뒤 앱이 새로 연 턴 0건 세션**입니다(요약 라우트 중첩). 벽시계 전환은 TC-22 때문에 택하지 않았고, **턴 0건 세션을 `openSession`에서 빼도록** 계약 v1.12로 바꿨습니다.
> - **남은 것**: 앱 라우트 수정 — `../app/summary-route-restarts-session.md`
>
> 아래 본문은 **요청 당시 원문**입니다. 확정된 최신 값은 계약 문서를 보세요.

- 요청자: 앱
- 대상: 백엔드
- 관련: `../../02-architecture/api-contract.md` §2-2 · PRD FR-015 · NFR-06 · spec F2-03

---

## 실측

46초 정도 대화하고(**AI 응답 정상**, 턴이 오갔습니다) 화면을 벗어난 뒤 홈의 이어하기 카드입니다.

> 남은 시간 **7분** · 원래 **7분** 중 이미 쓴 시간을 뺀 값입니다

앱은 이 두 값을 서버 값 그대로 씁니다.

| 화면 | 계산 | 서버가 준 값 |
| --- | --- | --- |
| 남은 시간 | `openSession.remainingSec` | **420** |
| 원래 | `usedSec + remainingSec` | **420** → 따라서 **`usedSec = 0`** |

**새로고침(F5) 후에도 같습니다.** 앱 캐시나 적재 경쟁이 아닙니다 — 새로고침은 앱을 통째로 다시 띄우고 `/me`를 새로 부릅니다.

## 계약·요구사항과 어긋납니다

- **§2-2**: `remainingSec` = `hardCutSec − usedSec`. *"이어하기해도 **원가 상한이 유지되도록** 남은 시간만 준다"*
- **PRD FR-015**: 이어한 세션의 남은 시간은 **`하드컷 − 이미 사용한 시간`**
- **spec F2-03 수용 기준**: *"7분 초과 세션이 생성되지 않는다. 세션당 원가 상한 $0.49가 지켜진다"*

**지금은 46초를 쓰고 나가도 7분이 새로 주어집니다.** 6분 50초를 쓰고 나가도 마찬가지일 것으로 보입니다 — 그렇다면 상한이 사실상 없습니다.

## 짐작 — 확인만 부탁드립니다

**열린 세션에서는 `usedSec`을 계산하지 않고 0을 주는 것 아닌지** 봐주세요. 종료 시점에만 채우는 컬럼이라면 `GET /me`가 그 값을 그대로 읽어 0이 됩니다.

**v1.11에서 `durationSec`을 「첫 턴~마지막 턴」으로 바꾸셨는데, `usedSec`은 계약에 「시작부터」라고 적혀 있습니다.** 두 값의 목적이 다르니 그 구분이 맞다고 봅니다 — **`usedSec`은 원가 상한을 지키는 값이라 벽시계(`now − started_at`)가 맞습니다.** Hume은 연결 시간으로 과금하지, 말한 시간으로 과금하지 않습니다. 「화면만 열어 둔 시간」이 들어가는 것도 그 목적에서는 정확합니다.

## 부탁

**① 열린 세션의 `usedSec`이 실제 경과를 반영하게 해주세요.**

**② 회귀 테스트 한 줄** — 세션 시작 → n초 뒤 `GET /me` → `openSession.remainingSec < hardCutSec`. 지금은 이 단언이 실패할 것입니다.

**③ 이어하기 응답(§2-5-1)의 `remainingSec`도 같이 봐주세요.** 앱은 그 값을 그대로 세션의 하드컷으로 씁니다 — 거기도 420이 오면 이어한 대화가 7분을 새로 받습니다.

## 곁다리 — 끝낸 세션이 잠깐 「열려 있음」으로 옵니다

같은 `openSession`이라 여기 적습니다. **`POST /end` 응답을 받은 뒤에 `GET /me`를 불렀는데도 방금 끝낸 세션이 `openSession`으로 돌아왔습니다** (2026-09-14 테스트 2건). 홈에 「이어서 이야기할까요?」가 떴고, **새로고침하면 사라졌습니다** — 몇 초 뒤의 같은 질문에는 정답이 옵니다.

앱은 `end` 응답을 **받은 다음에** `/me`를 무효화하므로 순서는 맞습니다. 읽기 복제 지연이나 종료 처리의 비동기 구간이 아닐지 봐주세요.

**앱에서는 이미 가려 뒀습니다** — 방금 우리가 닫은 세션 id 하나만 홈에서 무시합니다. 다만 그건 화면을 가리는 것이지 값이 맞아진 것은 아니라, 원인은 확인해 주시면 좋겠습니다. **급하지 않습니다.**

## 앱 쪽은 이렇습니다

- 두 숫자 모두 **서버 값을 그대로** 씁니다. 계산하거나 보정하지 않습니다 (`SessionClock.spell`)
- 표시는 회귀 테스트로 묶여 있습니다 (`test/session_clock_test.dart` — `remainingSec: 282` → 「4분 42초」, `usedSec + remainingSec: 420` → 「7분」)
- **고쳐 주시면 앱은 그대로 맞습니다.** 이어한 세션의 하드컷 타이머도 `remainingSec`을 그대로 쓰므로 함께 정상이 됩니다
