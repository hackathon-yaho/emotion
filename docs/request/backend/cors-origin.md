# CORS 허용 오리진 요청 — 앱이 배포됐습니다

> **상태: ⏳ 회신 대기** (요청 2026-09-04)
> 회신은 `../../response/app/cors-origin.md`에 들어옵니다.
> **막고 있는 작업**: 배포된 웹앱에서 **모든 API 호출.** 허용 전에는 F1-01 로그인부터 실패하므로, 앱은 그때까지 샘플 데이터로 화면만 그립니다. 백엔드가 아직 구현 중이라 지금은 실제로 막히지 않지만, **연동 시작 시점에 반드시 필요합니다.**

- 요청자: 앱(프론트엔드)
- 대상: 백엔드
- 관련 문서: `../../02-architecture/api-contract.md` §1-1 / `../../00-context/prd.md` §14-4

---

## 배경

앱을 GitHub Pages에 배포했습니다. **배포 주소가 정해지면서 오리진이 확정됐습니다.**

```
https://hackathon-yaho.github.io/emotion/
```

앱과 백엔드가 **서로 다른 오리진**이므로, 백엔드가 CORS로 이 오리진을 허용하지 않으면 브라우저가 모든 요청을 차단합니다. 서버 로그에는 요청이 도달하지도 않고, 앱에는 네트워크 오류로만 보여서 **원인 추적이 오래 걸리는 종류의 실패**입니다.

주소가 없던 동안에는 나오지 않던 항목이라 뒤늦게 요청합니다.

## 요청

| 항목 | 값 |
| --- | --- |
| 허용 오리진 (배포) | `https://hackathon-yaho.github.io` |
| 허용 오리진 (로컬 개발) | `http://localhost:*` — Flutter가 실행마다 포트를 바꿉니다. 고정이 필요하면 알려주세요, `--web-port`로 고정하겠습니다 |
| 허용 메서드 | `GET`, `POST`, `DELETE`, `OPTIONS` |
| 허용 헤더 | `Authorization`, `Content-Type` |
| 프리플라이트 | `OPTIONS`에 200/204 응답. **인증 없이 통과**해야 합니다 — 프리플라이트에는 `Authorization` 헤더가 실리지 않습니다 |
| 자격증명 | **불필요.** JWT를 `Authorization` 헤더로 보내고 쿠키를 쓰지 않으므로 `Allow-Credentials`는 켜지 않아도 됩니다 |

**오리진에 경로가 없다는 점을 유의해 주세요** — `https://hackathon-yaho.github.io/emotion/`이 아니라 `https://hackathon-yaho.github.io`입니다. 브라우저가 보내는 `Origin` 헤더에는 경로가 없습니다. 여기서 자주 어긋납니다.

## 결정을 요청하는 것

1. 위 오리진을 허용해 주실 수 있는지.
2. **로컬 개발 오리진을 와일드카드로 열 수 없다면** 고정 포트를 정해 주세요 (예: `http://localhost:5173`). 앱이 그 포트로 실행하겠습니다.
3. 스테이징·운영 환경이 갈리면 각각 어떤 오리진을 허용하는지.

## 함께 알려드리는 것 (요청 아님)

- **제품 이름이 정해지면 커스텀 도메인을 붙일 예정입니다** (PRD §14-6). 그때 오리진이 한 번 더 바뀌므로, 설정을 **환경변수로 두고 목록으로 받는 형태**를 권합니다 — 코드에 박으면 그때 또 배포해야 합니다.
- 앱은 `Authorization: Bearer <JWT>`만 쓰고 **쿠키·세션을 쓰지 않습니다.** 계약서 §1-1 그대로입니다.
- **Hume EVI 연결은 CORS와 무관합니다** — 앱이 `wss://api.hume.ai`로 직접 붙는 WebSocket이고 백엔드를 거치지 않습니다(PRD §6).
- 배포는 `app/` 변경 시 GitHub Actions가 자동으로 합니다. `analyze`·`test`·`build`가 통과해야 배포되므로, 깨진 앱이 올라가는 일은 없습니다.
