# `humeConfigId` 필드 추가 요청 — EVI 연결에 Config ID가 필요합니다

> **상태: ⏳ 회신 대기** (요청 2026-09-03)
> 회신은 `../../response/app/hume-config-id.md`에 들어옵니다.
> **막고 있는 작업**: **CLM 전환 시점의 F2-02 EVI 연결.** 앱이 EVI 기본 LLM으로 붙는 동안(프레임워크 스파이크·화면 개발)은 막히지 않지만, 대화 두뇌를 우리 AI서버로 돌리는 순간부터 Config ID 없이는 연결이 성립하지 않습니다. `live-turn-signal.md`보다 **우선순위가 높습니다** — 그쪽은 S07·데모 모드라 도그푸딩을 막지 않지만, 이건 9/10 도그푸딩이 갭 계산까지 포함하는 순간 막습니다.

- 요청자: 앱(프론트엔드)
- 대상: 백엔드 (Hume 콘솔의 Config 생성·소유는 AI 담당과도 걸립니다 — 아래 5번)
- 관련 문서: `../../02-architecture/api-contract.md` §2-4·§2-5-1·§4 / `../../00-context/spec.md` F2-01·F2-02 / `../../00-context/prd.md` FR-013, NFR-04

---

## 배경 — 실제 handshake를 확인했습니다

앱 프레임워크 결정을 위해 **Hume 공식 Flutter 예제를 웹으로 빌드해 브라우저에서 실행**했습니다(2026-09-03). EVI 연결 URL이 이렇습니다.

```
wss://api.hume.ai/v0/evi/chat?access_token={토큰}&config_id={구성ID}
```

- **`access_token`은 계약서 §2-4의 `humeAccessToken`과 1:1로 맞습니다.** 예제 자체가 자기 서버에서 액세스 토큰을 받아오는 경로(`MY_SERVER_AUTH_URL`)를 이미 갖고 있어서, FR-013·NFR-04의 단기 토큰 구조가 예제 그대로 성립합니다. 이 부분은 손댈 게 없습니다.
- **`config_id`에 해당하는 필드가 계약서에 없습니다.** `POST /api/session/start` 응답(§2-4)에도, `resume`(§2-5-1)에도 없습니다.

Config ID가 필요한 이유는 **CLM 때문**입니다. 우리 AI서버가 대화 두뇌가 되려면 Hume 콘솔의 EVI Config에 CLM 엔드포인트를 등록해야 하고(계약서 §4), 앱은 그 Config를 지정해 연결해야 합니다. 지정하지 않으면 EVI 기본 LLM이 응답하므로 **갭 계산·되묻기·태깅이 전부 우리 파이프라인을 타지 않습니다.**

## 왜 앱에 상수로 박지 않고 서버가 내려줘야 하는가

1. **계약서가 이미 같은 판단을 했습니다.** §2-4가 `softWrapSec`·`hardCutSec`에 대해 "서버가 내려주는 값을 쓰고 앱에 상수로 박지 않는다 — 정책 변경 시 배포 없이 바꾸기 위함"이라고 정해뒀습니다. Config ID는 같은 성격입니다.
2. **환경마다 다른 Config를 써야 합니다.** CLM 엔드포인트 URL이 Config에 박히므로 로컬·스테이징·배포가 각각 다른 Config가 됩니다. 앱에 박으면 환경마다 빌드가 갈립니다. **웹으로 배포하면 빌드가 곧 배포라 이 문제가 더 직접적입니다.**
3. **Config 교체는 AI 담당의 작업입니다.** 프롬프트·CLM 주소를 바꾸려고 앱 재배포를 기다려야 하는 구조는 3인 병렬 개발에서 병목이 됩니다.

## 제안

`POST /api/session/start`(§2-4)와 `POST /api/session/{id}/resume`(§2-5-1) 응답에 **`humeConfigId`** 를 추가.

```json
{
  "sessionId": "sess_9c1d4e",
  "humeAccessToken": "hume_at_...",
  "humeConfigId": "cfg_8a12ff",
  "...": "기존 필드 그대로"
}
```

| 항목 | 제안 |
| --- | --- |
| 타입 | 문자열 |
| null 허용 | **불가.** 없으면 앱이 대화를 시작할 수 없으므로, 발급 실패는 기존 503 `HUME_TOKEN_ISSUE_FAILED`와 같은 경로로 처리하는 것이 자연스럽습니다 |
| 출처 | 백엔드 환경변수 (Hume API 키와 같은 자리) |
| 앱 동작 | 받은 값을 handshake 쿼리에 그대로 넣습니다. 저장하지 않습니다 |

## 결정을 요청하는 것

1. 필드 추가에 동의하는지.
2. 필드명 `humeConfigId`로 괜찮은지.
3. `resume` 응답에도 포함할지 (같은 Config로 이어야 맥락 복원이 성립합니다).
4. 발급 실패를 기존 `HUME_TOKEN_ISSUE_FAILED`로 묶을지, 별도 코드를 둘지.
5. **Hume 콘솔의 Config를 누가 만들고 소유하는지.** CLM 엔드포인트 URL을 넣는 작업이라 AI 담당 몫으로 보이는데, API 키를 쥔 사람과 같아야 콘솔 접근이 됩니다. 정해지면 그쪽에 별도 요청을 내겠습니다.

## 회신 전 앱이 하는 것

로컬 `.env`의 값으로 개발을 진행하고, 필드가 생기면 즉시 교체합니다. **앱 저장소에 Config ID를 상수로 커밋하지 않습니다** — 위 2번 이유 때문입니다.

## 함께 알려드리는 것 (요청 아님)

- **`custom_session_id`는 앱이 붙입니다.** spec F2-02와 CLM 계약 §4가 이걸로 세션을 식별하는데 공식 예제에는 없어서, 앱이 handshake 쿼리에 추가합니다. 계약 변경은 필요 없습니다.
- **Hume 요금 페이지의 현재 표기가 PRD와 다릅니다.** Free 플랜의 추가 EVI 사용료가 **$0.06/분**으로 적혀 있습니다(PRD §2.1·§11은 $0.07/분 기준). PRD §2.5·§14-3이 "결제 전 콘솔 실측 확인"을 백엔드 담당 과제로 잡아둔 항목이라, 확인하실 때 §11 비용 계산도 같이 보시면 좋겠습니다. **Free 티어는 월 5분**이라 도그푸딩 90분에는 쓸 수 없습니다.
