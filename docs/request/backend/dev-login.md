## 부탁

**`POST /api/auth/dev`** — 본문 없음(`{}`), 인증 헤더 없음. **응답은 §2-1 `POST /api/auth/kakao`와 같은 모양**으로 주세요.

```json
{ "jwt": "...", "expiresAt": "...", "profileId": "...", "isNewUser": false }
```

앱은 이 응답을 카카오 로그인과 **똑같이** 처리합니다(`AuthResult.fromJson` → `completeLogin`). 필드가 같으면 앱 변경은 0입니다.

## 앱 쪽은 이미 이렇게 돼 있습니다

| 자리 | 지금 |
| --- | --- |
| 온보딩(S00) | 카카오 버튼 **아래**에 조용한 글자 「로그인 없이 둘러보기」 |
| 누르면 | `POST /api/auth/dev` → 성공 시 홈으로 |
| **경로가 아직 없으면(404)** | 「둘러보기는 아직 준비되지 않았습니다.」 — 고장으로 보이지 않게 |
| 네트워크 실패 | 「연결이 되지 않습니다.」 |

**배포돼 있습니다.** 지금 눌러 보면 404 문구가 나옵니다. 경로가 생기는 순간 그대로 동작합니다.

## 판단은 백엔드에 맡기는 것

- **어느 계정으로 넣어 줄지** — 고정 심사 계정 하나인지, 호출마다 새 계정인지. 앱은 어느 쪽이든 상관없습니다. 다만 **심사위원 여러 명이 동시에** 쓸 수 있으니, 한 계정을 공유하면 서로의 대화·기록이 섞여 보입니다. 호출마다 새 프로필(`isNewUser: true`)이 심사에는 더 자연스러워 보입니다 — 판단 맡깁니다
- **막을 장치** — 이 경로는 사실상 무인증 로그인입니다. 배포본에 열어 두는 것이라 최소한 **호출 빈도 제한**은 있어야 할 것 같습니다. 제출 뒤 닫을지, 환경변수로 끌 수 있게 할지도 함께 정해 주세요
- **탈퇴(§2-3)와의 관계** — dev 계정은 카카오 연결이 없으니 `kakaoAuthCode` 없는 본문으로 오게 됩니다. 이미 선택 본문이라 문제없어 보이지만 확인만 부탁드립니다

## 계약서
