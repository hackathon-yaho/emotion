## 배경

PRD·spec·계약서를 통독하면서 실시간 턴 처리 설계에 **논리적으로 성립하지 않는 지점 하나**와 **제품 핵심 지표를 무너뜨릴 수 있는 지점 하나**를 발견했습니다. 둘은 같은 수정으로 해결되므로 한 요청에 묶습니다. 문서는 잘 쓰였고 방향은 그대로입니다 — 고칠 곳은 §9.1의 호출 구조 하나예요.

## 발견 1 — 텍스트 valence의 순환 의존

§9.1과 F3-02는 텍스트 valence를 **응답 LLM 호출의 첫 줄 출력**(`<v>0.70</v>`)으로 받습니다. 그런데 F4-01은 **갭 초과 신호를 그 호출의 프롬프트에 주입**해서 되묻기를 만들라고 합니다.

갭 = |텍스트 valence − 음성 valence|이고 텍스트 valence는 호출이 끝나야 나오므로, **한 호출 안에서 그 결과를 같은 호출의 입력으로 쓸 수 없습니다.** 지금 문서대로 구현하면 셋 중 하나가 됩니다:

| 경로 | 결과 | 문제 |
| --- | --- | --- |
| (a) 직전 턴의 갭으로 이번 턴 되묻기 | 되묻기가 한 턴 늦음 | 데모 1·2번 장면("지친 톤에서 AI가 **먼저** 되묻는다")이 성립하지 않음 |
| (b) LLM에 음성 valence를 주고 스스로 비교시킴 | 판정을 LLM이 함 | FR-022(규칙)·FR-054(LLM은 표현만) 위반. 결정성(§1.4 재현성 ±0.1) 깨짐 |
| (c) 텍스트 valence를 별도 호출로 먼저 얻음 | 성립 | FR-021("별도 호출을 추가하지 않는다")과 충돌 — **FR-021 개정 필요** |

## 발견 2 — 두 채널이 독립적이지 않음

Hume CLM은 요청의 `messages[].models.prosody.scores`에 **프로소디 48종 점수를 그대로 실어** 보냅니다(계약서 §4). 텍스트 valence를 매기는 LLM이 같은 메시지에서 `Tiredness: 0.71`을 보고 있으면, "오늘 완전 괜찮았어요"의 텍스트 valence를 낮게 매기게 됩니다. 그러면 **갭이 스스로 줄어듭니다.**

갭의 전제는 "텍스트는 텍스트만 보고, 음성은 음성만 본다"인데, 문서 어디에도 **텍스트 valence 산출 시 프로소디를 가린다**는 조항이 없습니다. 이대로면 제품의 서명 기능(두 선 그래프, 되묻기)이 구조적으로 약해집니다. 발표에서 "같은 문장을 밝게/지치게 말하면 갭이 갈린다"를 시연할 때 갭이 기대보다 작게 나올 위험이 여기서 옵니다.

## 제안 — 하나의 수정으로 둘 다 해소

§9.1을 아래로 바꾸는 것을 제안합니다. **판정은 여전히 서버 규칙**이고, LLM 호출은 "경량 1 + 응답 1"입니다.

```
① Hume → AI서버   messages 수신 (전사 + prosody.scores)
② 병렬 ┬ voice_valence  prosody.scores → 매핑표 → ±1          ← 규칙, 즉시
       └ text_valence   전사 텍스트만 입력 → 경량 호출 → ±1     ← 프로소디 미노출, temp 0, 타임아웃 400ms
③ gap 판정          |text − voice| vs 임계값                     ← 규칙
④ 위기 규칙 검사     키워드 매칭                                   ← 규칙, 항상 동작
⑤ 응답 LLM 호출     입력: 대화 이력 + gapTriggered 플래그 + 위기 규칙 결과
                    prosody 48종 원본은 전달하지 않는다 — 계산된 플래그만
                    출력: 첫 줄 <m>{"tags":[…],"crisis":bool}</m> + 줄바꿈 + 응답 본문
⑥ SSE 반환          <m> 제거 후 본문만 Hume으로
⑦ 로그 적재          POST /internal/turns (비동기)
```

**지연 계산은 정직하게**: ②의 경량 호출은 음성 valence와는 병렬이지만 **⑤ 앞에 직렬**로 붙습니다. 평시 **+300~400ms**입니다. NFR-01(p95 2초)이 깨지면 대안이 있습니다 — **추측 실행**: ⑤를 플래그 없이 즉시 시작하고 ②③을 병렬로 돌린 뒤, 갭이 임계를 넘은 경우에만 ⑤ 스트림을 폐기하고 플래그를 넣어 재호출. 트리거는 드물어야 정상이므로 p95는 영향이 없고, 트리거된 턴만 +1호출입니다. **기본안(직렬)으로 시작해 TC-12로 재고, 깨지면 추측 실행으로 전환**을 권합니다.

텍스트 valence 산출 수단은 AI 담당 결정 사항입니다. 후보 둘:
- (a) **경량 LLM 호출**(JSON, temp 0) — 가장 빨리 붙음
- (b) **로컬 한국어 감성 모델**(KoELECTRA 계열, CPU ~50ms) — 결정적·오프라인. §1.4 재현성 지표를 텍스트 쪽에서 자동 충족. 여유가 있을 때

## 결정을 요청하는 것

1. 발견 1·2에 동의하는지. 동의하지 않으면 **어떤 경로로 같은 호출 안에서 갭을 입력으로 쓸 수 있는지** 알려주세요.
2. 제안 구조(경량 호출 분리 + 프로소디 미노출)를 채택할지, 채택하면 **텍스트 valence 수단 (a)/(b)** 중 무엇으로 시작할지.
3. 추측 실행을 처음부터 넣을지, 기본안으로 시작할지.

## 함께 확인하면 좋은 것 (요청 범위 밖, 참고)

- **§14-1 매핑표와 §14-5 고정 임계값은 같은 20쌍 데이터로 같은 날 정해야** 서로 맞습니다. 매핑표는 긍정/부정 이분 **±1 균일 가중치**로 시작해 자유도를 최소화하고(20쌍 과적합 방지), 갭 방향 일치율 ≥90%가 안 나올 때만 분류를 재검토하는 절차를 권합니다.
- 이 설계는 Hume이 죽으면 데모가 죽습니다. 녹화 폴백(NFR-02)은 있으니 **전환 판단 기준**("연결 실패 2회 또는 첫 응답 5초 초과 시 영상으로")과 전환 문장을 §13 대본에 넣어두면 무대에서 망설이지 않습니다.
