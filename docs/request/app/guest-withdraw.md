## 무엇이 걸리나

`POST /api/auth/dev`(§2-1-1)로 들어온 사용자는 **카카오 계정과 연결돼 있지 않습니다.** 그런데 설정 화면의 탈퇴는 **샘플 모드가 아니면 항상** 카카오 인가 URL로 보냅니다.

```dart
final url = ref.read(dataModeProvider) == DataMode.sample
    ? null
    : KakaoLogin.authorizeUrl(...);
```

| 투표자 | 결과 |
| --- | --- |
| 카카오 계정이 없다 | 동의 화면에서 막혀 **탈퇴를 못 한다** |
| 카카오 계정이 있다 | **자기 카카오 계정을 인가하게 된다.** 서버가 받은 코드로 unlink를 부르는데, 그 카카오 계정은 우리 앱과 연결된 적이 없다 — 의미 없는 호출이고, 투표자는 "왜 카카오 로그인을 하라지?"를 겪는다 |

데이터 삭제는 **본문 없는 `DELETE /api/account`만으로 끝납니다**(§2-3, 서버 테스트로 확인). 카카오 왕복이 필요 없습니다.

## 부탁

**둘러보기로 들어온 세션이면 샘플 모드와 같은 길**(`url == null` → `deleteAccount()` 본문 없이)로 보내 주세요.

앱이 "둘러보기로 들어왔다"를 아는 방법은 앱이 정하시면 됩니다. 백엔드가 떠올린 두 가지입니다.

- **(추천) `_startDev` 성공 시 저장소에 표시를 남긴다.** JWT와 같은 수명이고 `reset()`에서 같이 지워집니다. 계약 변경 없음
- **`GET /api/me`에 `isGuest`를 달아 달라고 요청한다.** 서버에서 한 줄입니다(`account_profile` 연결 유무). 저장소 표시가 불편하면 말씀해 주세요 — 계약 §2-2에 필드를 추가합니다

## 같이 봐 주시면 좋은 것 (선택)

- **탈퇴 확인 문구** — 「같은 카카오 계정으로 다시 시작하면 새 사용자가 됩니다.」가 둘러보기 사용자에게는 맞지 않습니다
- **429 문구** — `POST /api/auth/dev`가 분당 30회를 넘으면 **429 `TOO_MANY_REQUESTS`**가 옵니다. 지금은 「로그인이 완료되지 않았습니다. 다시 시도해 주세요.」로 떠서 틀리진 않습니다. 바꾸려면 서버 `message`(「지금 요청이 많습니다. 잠시 후 다시 시도해 주세요.」)를 그대로 쓰시면 됩니다
