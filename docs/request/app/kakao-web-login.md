## 배경 — spec이 "SDK가 반환한 액세스 토큰"이라고만 씁니다

spec F1-01의 입력이 **"카카오 SDK가 반환한 액세스 토큰"**이고, 계약 §2-1이 그걸 그대로 받습니다.

```json
POST /api/auth/kakao
{ "kakaoAccessToken": "AAAA..." }
```

**네이티브 앱이면 자명한 흐름입니다.** 카카오톡 앱으로 넘어갔다 돌아오면 SDK가 토큰을 손에 쥐여 줍니다.

**그런데 우리 배포는 웹입니다**(PRD §14-4, GitHub Pages). 웹에서는 카카오 로그인이 **리다이렉트로 인가 코드(`code`)를 받아 오는 흐름**이 기본이라, "SDK가 토큰을 반환한다"가 그대로 성립하는지 확인이 필요합니다.

`app/pubspec.yaml`에 아직 카카오 의존성이 없고 `onboarding_screen.dart:78`이 `TODO(app): 카카오 SDK 로그인` 상태라, **지금이 정하기 좋은 시점**으로 보입니다.

## 확인을 요청하는 것

### 1. 앱이 백엔드에 넘기는 게 **액세스 토큰**입니까, **인가 코드**입니까?

| 앱이 넘기는 것 | 백엔드가 하는 일 | 계약 §2-1 |
| --- | --- | --- |
| **액세스 토큰** (지금 계약) | `access_token_info`로 `app_id` 대조 → `/v2/user/me` | **그대로** |
| **인가 코드(`code`)** | 백엔드가 `code`를 토큰으로 교환(REST 키·`redirect_uri` 필요) → 위와 동일 | **개정 필요** — 필드명·`redirect_uri` 전달 여부 |

**어느 쪽이든 백엔드는 만들 수 있습니다.** 코드 교환 방식이면 오히려 **REST 키가 서버에만 있어서** 더 낫습니다. 정해 주시면 그대로 맞추겠습니다.

다만 **정하기 전에 코드를 짜면 한쪽을 버리게 되므로** 먼저 여쭙니다.

### 2. 리다이렉트 방식이면, `redirect_uri`를 어디로 두실 겁니까?

- **앱 주소로 받고 앱이 `code`를 백엔드에 넘기는** 방식인지
- **백엔드 주소로 받고 백엔드가 앱으로 되돌려보내는** 방식인지

**전자를 권합니다.** 후자는 백엔드가 프론트 URL로 리다이렉트해야 하는데, GitHub Pages의 SPA + `/emotion/` 경로라 복잡해지고 **CORS 회신에서 정리한 "쿠키 안 씀" 전제**와도 어긋나기 쉽습니다.

### 3. ~~카카오 콘솔 등록은 앱 쪽에서 하시나요?~~ → **백엔드가 합니다** (2026-09-04 해소)

제가 카카오 디벨로퍼스에 프로젝트를 만들어서 **콘솔 등록은 백엔드가 합니다.** 다만 **등록할 주소는 앱 배포 주소**라 확정을 받아야 합니다 — 아래 "추가 (2026-09-04)" 1번으로 옮겼습니다.

**커스텀 도메인이 붙으면 한 번 더 등록**해야 합니다(PRD §14-6). CORS 오리진과 **같이 바뀌는 항목**이라 그때 같이 알려주시면 됩니다.

## 백엔드가 이미 정한 것 (참고)

회신과 무관하게 확정된 부분입니다.

- **토큰 검증에 `app_id` 대조를 넣습니다** — `GET /v1/user/access_token_info`로 그 토큰이 우리 앱에서 발급된 것인지 확인합니다. 안 하면 아무 카카오 앱에서 발급된 토큰이든 통과합니다. spec F1-01 ③에 명시했습니다
- **저장하는 식별자는 `/v2/user/me`의 `id`(회원번호)** 입니다. 컬럼명을 `kakao_sub` → **`kakao_id`**로 고쳤습니다 (`sub`은 OIDC 용어인데 우리는 OIDC를 쓰지 않습니다). **백엔드 내부 컬럼이라 앱에는 영향이 없습니다**
- **JWT는 응답 바디로만 갑니다.** 쿠키를 쓰지 않는다는 CORS 회신 내용 그대로입니다

## 함께 알려드리는 것 (요청 아님)

- **리프레시 토큰을 두지 않습니다.** JWT 만료 7일이고 만료되면 카카오 재로그인입니다(계약 §1-1, spec F1-02). 매일 쓰는 앱이라 7일이면 실사용 중 만료를 만날 일이 드뭅니다
- **카카오 회원번호는 앱마다 다릅니다.** 같은 사람도 다른 카카오 앱에서는 다른 번호를 받으므로, 콘솔에서 앱을 새로 만들면 **기존 계정과 연결되지 않습니다.** 도그푸딩 중에 앱을 갈아엎지 않는 편이 좋습니다

# 추가 (2026-09-04) — 카카오 콘솔을 만들었습니다

**카카오 디벨로퍼스에 프로젝트를 만들어 뒀습니다.** 소유는 백엔드(팀장)이고 **콘솔 등록도 백엔드가 합니다**(위 3번 정정). 그에 따라 세 가지가 생겼습니다.

## 1. `KAKAO_JS_KEY`를 넣어주세요 — Phase 1을 막습니다

`app/lib/core/config/env.dart`가 이미 `KAKAO_JS_KEY`를 받게 돼 있고, 배포 워크플로도 `vars.KAKAO_JS_KEY`를 읽습니다. **값만 비어 있습니다.**

- **JavaScript 키를 GitHub repo variable(`KAKAO_JS_KEY`)에 넣어 주세요.** 제가 콘솔에서 값을 전달하겠습니다 — 어떤 경로로 드리면 될지 알려주세요(저장소에는 넣지 않습니다)
- **콘솔 등록은 제가 합니다.** 대신 **등록할 주소를 확정해 주세요** —
  - 플랫폼(Web) 사이트 도메인: `https://hackathon-yaho.github.io` 로 알고 있습니다. 맞습니까?
  - **Redirect URI**: 리다이렉트 흐름을 쓰신다면 정확한 경로가 필요합니다 (예: `https://hackathon-yaho.github.io/emotion/auth/kakao`)
  - 로컬 개발 주소: CORS는 `http://localhost:*`로 열었지만 **카카오 콘솔은 와일드카드를 안 받습니다.** 개발용으로 쓸 포트를 하나 정해 주세요

> **JavaScript 키는 웹 번들에 노출되는 것이 정상입니다.** 카카오가 **도메인 화이트리스트로** 보호하는 구조라, 콘솔에 등록한 도메인에서만 동작합니다. 이건 Hume API 키를 앱에 내리지 않는 것(FR-013·NFR-04)과 성격이 다릅니다 — Hume 키는 과금이 붙는 비밀이고, 카카오 JS 키는 공개 전제로 설계된 값입니다.

## 2. 동의항목은 **회원번호만** 열었습니다 (통보)

닉네임·프로필 사진·이메일을 **전부 비활성**으로 둡니다.

- `account` 테이블에 회원번호 말고 담을 컬럼이 **아예 없습니다.** 받아도 버립니다
- PRD §5.1 "식별자 분리"와 S00 고지(F10-04)가 **콘솔 설정으로도 증명**됩니다
- **로그인 동의 화면이 가장 짧아져** 첫 화면 이탈이 줄어듭니다

**화면에 사용자 이름을 쓸 계획이 있으면 지금 말씀해 주세요.** `design-system.md`를 봤을 때는 이름을 쓰는 화면이 없어서 이렇게 정했습니다. 나중에 열면 **이미 가입한 사용자는 재동의를 받아야** 합니다.

## 3. 탈퇴 시 카카오 연결 해제를 앱이 맡아 주세요 (F10-03, Phase 6)

지금 F10-03은 DB 10개 테이블만 지웁니다. 그러면 **사용자의 카카오 "연결된 서비스" 목록에 우리 앱이 그대로 남습니다.** PRD §5.1과 F10-04 고지가 "삭제 권한"을 신뢰의 핵심으로 내세우는데, 그 상태면 "모두 지웠다"가 절반만 참입니다.

**순서를 이렇게 부탁드립니다.**

```
① 앱이 DELETE /api/account 호출
② 백엔드가 10개 테이블 삭제 → 204
③ 204를 받은 뒤 앱이 카카오 SDK로 unlink
```

- **②가 먼저인 이유** — 뒤집으면 "카카오는 끊겼는데 우리 데이터는 남은" 상태가 생깁니다. **사용자 데이터가 먼저 사라져야** 합니다
- **③이 실패해도 탈퇴는 성립합니다.** 우리 데이터는 이미 없으니, 실패를 사용자에게 오류로 보여주지 말고 안내 정도로 끝내시면 됩니다
- **백엔드가 하지 않는 이유** — 서버에서 unlink를 하려면 카카오 **Admin 키**가 필요한데, 그건 모든 사용자를 조작할 수 있는 가장 강한 키입니다. **서버에 두지 않기로 했습니다.** 앱은 그 시점에 본인 액세스 토큰이 있어 자기 계정만 끊습니다
- spec F10-03 담당이 이미 `A/C`라 화면 흐름도 앱에 있습니다. spec에 이 처리를 명시해 뒀습니다

## 참고 — 백엔드가 함께 확정한 것

| 항목 | 값 |
| --- | --- |
| 앱 ID 대조 | `KAKAO_APP_ID` 환경변수로 `access_token_info`의 `app_id`와 대조 |
| Admin 키 | **서버에 두지 않음** |
| 저장하는 값 | `/v2/user/me`의 `id` 하나 (`account.kakao_id`) |
