# 「생각 중」이 답이 오기 전에 「듣고 있습니다」로 한 번 튑니다

> **막고 있는 작업**: 없습니다. 화면 표시만의 문제이고 대화·저장은 정상입니다. 다만 **도그푸딩·시연에서 계속 보입니다.**

## 증상

배포본(2026-09-16 08:46 KST 세션)에서 상태 고리가 이렇게 돕니다.

```
듣고 있습니다 → 생각하고 있습니다 → 듣고 있습니다 → 말하고 있습니다 → 듣고 있습니다
                                    ^^^^^^^^^^^^^ 여기가 끼어듭니다
```

**대화마다 다릅니다.** 어떤 턴은 정상(`생각 → 말하기`)이고 어떤 턴만 「듣고 있습니다」가 낍니다.

## 원인 — 경로를 전부 세어보니 하나만 남습니다

`EviMicLive`를 내보내는 곳은 **`_releaseMic()` 한 곳뿐**이고(`evi_service.dart:401`), 화면은 그것을 **조건 없이** 「듣고 있습니다」로 그립니다(`conversation_screen.dart:468`).

`_releaseMic()` 호출부 6개를 「생각 중」 구간(= `user_message` 도착 후 `assistant_message` 도착 전, 실측 p95 3.2초)에 발동 가능한지로 걸러봤습니다.

| 호출부 | 발동 시점 | 3.2초 안에 도나 |
| --- | --- | --- |
| `:180` 인사 유예 `_greetingGrace` | 세션 시작 1회 | ✗ 생각 중과 무관 |
| `:335` `_startHold` cap 타이머 | 보류 후 **1분** | ✗ |
| `:421` `releaseHold()` ← `_transcriptTimer` | 「말 다 했어요」 후 **5초** | ✗ 그리고 발동하면 「들은 말이 없습니다」 안내가 함께 뜹니다 |
| `:471` `assistant_message` 도착 시 재보류 | 타이머를 **거는** 시점이 `assistant_message`라 화면은 이미 「말하고 있습니다」 | ✗ |
| `:493` `assistant_end` → `_whenQuiet` | AI가 말을 마친 뒤 | ✗ 「말하고 있습니다」 다음 |
| **`:296` `_loudRun >= 3`** | **보류 중 마이크 레벨이 `_speechLevel`(8) 이상으로 3프레임 연속** | **✓ 이것만 남습니다** |

`_heardUser()`가 `holdForThinking()`으로 마이크를 보류하고 소리를 모으는 동안, `_sendAudio()`가 프레임마다 레벨을 재서 `_loudRun >= 3`이면 **"말을 시작했다"고 보고 그 자리에서 보류를 풉니다**(`flush: true`). 그 해제가 `EviMicLive`를 쏘고, 화면이 「듣고 있습니다」로 갑니다. 곧 `assistant_message`가 도착해 「말하고 있습니다」로 넘어갑니다 — **관찰된 순서 그대로입니다.**

**간헐적인 이유가 여기 있습니다.** 답을 기다리는 3초 남짓 동안 사용자가 소리를 냈는지에 달려 있습니다 — 방금 말을 마친 직후라 숨소리·"음…"·옷 스침이 곧잘 걸립니다. 조용하면 안 생깁니다.

## 배포 DB로 확인한 것 — 대화 자체는 멀쩡합니다

세션 `546562ae`(08:46:31~08:50:57 KST)의 `turn_log`입니다.

- user 10턴 / assistant 10턴, **완전한 1:1 교대. 없던 발화 턴은 0건입니다** — 보류가 풀리면서 내보낸 소리가 발화로 인정되진 않았습니다
- 턴 간격도 정상(16~31초)이고 `ops_error_log`에 이 세션 관련 오류 0건

**즉 화면 상태만 튀는 문제입니다.** 저장·분석·응답은 영향받지 않았습니다.

## 부탁드립니다

**`EviMicLive`를 「듣고 있습니다」와 같은 것으로 묶지 말아 주세요.** 이 이벤트의 뜻은 "마이크가 다시 열렸다"이지 "AI 답을 더는 기다리지 않는다"가 아닙니다. 생각 중에 보류가 풀리는 것은 **말을 더 해도 된다**는 뜻이고, 그때도 사용자는 여전히 답을 기다리는 중입니다.

```dart
case EviMicLive():
  // 생각 중이면 마이크가 열려도 「생각 중」이다 — 기다리는 것은 그대로다.
  if (_state != TalkState.thinking) setState(() => _state = TalkState.listening);
```

`_transcriptTimer`(5초) 경로는 `releaseHold()` 뒤에 **자기가 직접** `listening`으로 넘기고 있어서(`conversation_screen.dart` `_finishTurn`), 이 가드를 넣어도 막히지 않습니다. 확인하고 적었습니다.

**임계값 `_speechLevel = 8`은 건드리지 않아도 된다고 봅니다.** 낮추면 "말을 이어가면 그 자리에서 풀린다"는 원래 의도가 죽습니다. 화면 표시와 마이크 개폐를 분리하는 쪽이 맞아 보입니다 — 다만 판단은 맡깁니다.

## 확인해 보실 방법

`SHOW_ERROR_DETAIL`을 켜면 진단 줄에 `마이크 {micLevel} (최대 {micPeak})`이 나옵니다. **「생각 중」 동안 이 값이 8 위로 올라가는 턴에서만 「듣고 있습니다」가 끼는지** 보시면 위 진단이 맞는지 바로 갈립니다.

> 판정에 쓰이는 값은 `_lastLevel`(원값)이고 화면의 `micLevel`은 평활값이라 조금 늦게 따라옵니다. `micPeak`은 세션 내내 누적 최댓값이라 턴별 판정에는 못 씁니다.
