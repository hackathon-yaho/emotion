# 인가 URL은 REST 키로 만들어 주세요 — 혼용은 확인할 필요가 없어졌습니다

> **상태: ✅ 회신 완료** (요청 2026-09-05 · 회신 2026-09-05)
> 회신은 [`../../response/backend/kakao-rest-key-switch.md`](../../response/backend/kakao-rest-key-switch.md)에 있습니다.
> **결론**: 변수명 **`KAKAO_REST_KEY`** 확정 — **앱 코드·워크플로는 이미 바꿔 뒀습니다**(`env.dart`의 `Env.kakaoRestKey`, `app-web.yml`). 등록만 해 주시면 다음 배포에 들어갑니다. 값 전달은 사설 채널로 좋습니다 — 다만 **`INTERNAL_SHARED_SECRET`은 앱에 주지 마십시오**(웹 번들에 들어가면 누구나 내부 엔드포인트를 부릅니다). `unlink` 결정(리프레시 토큰 미보관)에 동의합니다.

## 물어보신 것 두 개, 둘 다 답이 나왔습니다

### 1. `client_id` 혼용 — **시험할 필요가 없습니다. 권하신 대로 REST 키로 갑니다**

권하신 방향(인가 URL도 REST 키)이 **제가 이미 실측한 경로**입니다. 어제 실계정 검증에 쓴 URL이 정확히 이것이었습니다.

```
https://kauth.kakao.com/oauth/authorize
  ?client_id={REST_API_KEY}&redirect_uri=http%3A%2F%2Flocalhost%3A3000%2F&response_type=code
```

여기서 받은 코드를 **REST 키 + 클라이언트 시크릿**으로 교환해 토큰을 받았고, 그 토큰으로 `/v2/user/me`까지 갔습니다. **JS 키로 인가한 코드를 REST 키로 교환할 수 있는지는 이제 물을 필요가 없습니다** — 그 경로를 안 쓰니까요.

**그래서 앱에 필요한 키가 REST API 키로 바뀝니다.**

| | 이전 | 지금 |
| --- | --- | --- |
| repo variable | `KAKAO_JS_KEY` | **`KAKAO_REST_KEY`** |
| 쓰는 곳 | SDK 초기화 | **인가 URL의 `client_id`** |
| 워크플로 | `app-web.yml`의 `--dart-define` | 같은 자리, 이름만 |
| 앱 코드 | `core/config/env.dart` | 같은 자리, 이름만 |

**변수명은 그쪽에서 정하셔도 됩니다.** `KAKAO_REST_KEY`가 편하면 그대로 쓰시고, 다른 이름이 좋으면 알려주세요 — **repo variable 등록은 제가 합니다**(말씀하신 대로 값이 앱으로 갈 필요가 없습니다). **이름만 확정해 주시면 그날 등록하겠습니다.**

> **REST 키가 앱 번들에 들어가는 것은 정상입니다.** 인가 URL에 실리는 값이라 어차피 주소창에 보입니다. 보호는 **클라이언트 시크릿(서버에만)** 과 **Redirect URI 화이트리스트**가 합니다 — 코드만으로는 토큰이 나오지 않습니다.

### 2. `unlink` — **사용자 액세스 토큰으로 됩니다. 추측이 맞습니다**

카카오 문서 확인했습니다. `POST /v1/user/unlink`는 두 방식을 다 받습니다.

| 방식 | 헤더 | 대상 지정 |
| --- | --- | --- |
| **사용자 토큰** | `Authorization: Bearer {ACCESS_TOKEN}` | **불필요 — 그 토큰의 주인** |
| 어드민 키 | `Authorization: KakaoAK {ADMIN_KEY}` | `target_id` 필수 |

**어드민 키를 서버에 두지 않는다는 결정을 그대로 지키면서 백엔드가 unlink할 수 있습니다.** 담당을 백엔드로 가져오겠습니다.

**다만 리프레시 토큰은 보관하지 않기로 했습니다.** 제안해 주신 두 안 중 재인가 쪽입니다.

- 액세스 토큰 6시간(실측 21599초) · 리프레시 토큰 2개월(실측 5183999초)입니다
- 보관하면 **모든 사용자의 2개월짜리 카카오 자격증명을 우리 DB가 들고 있게 됩니다.** 그 순간 "저장하는 것은 회원번호 하나"(PRD §5.1 · S00 고지 F10-04)라는 제품 주장이 길어집니다 — **음성 원본을 안 받고 동의항목을 회원번호만 연 것과 같은 줄에 있는 판단입니다**
- 지적하신 "탈퇴하려는 사람에게 다시 로그인"의 부담은, **이미 동의한 계정이면 동의 화면 없이 리다이렉트만 튀고 돌아오는 것이 보통**이라 실제 체감이 작을 것으로 봅니다. 만약 붙여보셨는데 동의 화면이 매번 뜨면 알려주세요 — 그때 다시 정합시다

## 계약 v1.6 — 올렸습니다

**§2-1** — 확정하신 개정안 그대로입니다.

```json
POST /api/auth/kakao
{ "kakaoAuthCode": "abcd...", "redirectUri": "http://localhost:3000/" }
```

**§2-3에 선택 본문이 생겼습니다** — 탈퇴 unlink용입니다.

```json
DELETE /api/account
{ "kakaoAuthCode": "abcd...", "redirectUri": "http://localhost:3000/" }
```

- **선택입니다.** 본문이 없으면 데이터만 지우고 **똑같이 204**입니다 — unlink 실패도 오류로 올리지 않습니다(우리 데이터는 이미 없습니다)
- 순서는 그대로 **삭제 → unlink → 204**입니다
- **F10-03은 Phase 6이라 지금 급하지 않습니다.** 라우트는 본문을 받게 해뒀고 처리는 그때 채웁니다

## 백엔드는 다 바꿔뒀습니다

- `redirectUri`를 **등록 목록과 대조**하고 아니면 **400**입니다 — 카카오를 부르기 전에 막습니다. 지적하신 "남의 주소로 인가 코드를 흘릴 수 있는 자리"를 테스트로 못 박았습니다
- **`app_id` 대조는 걷어냈습니다.** 말씀대로 필요가 없어졌습니다 — Phase 1의 유일한 미검증 항목이었는데 **항목 자체가 사라졌습니다**
- 등록값은 그대로입니다: `https://hackathon-yaho.github.io/emotion/` · `http://localhost:3000/`

## 확인만 부탁드립니다

1. **repo variable 이름** — `KAKAO_REST_KEY`로 갈까요? 확정되면 제가 등록합니다
2. **로컬용 값 전달 경로** — 사설 채널로 드리면 될까요? (`INTERNAL_SHARED_SECRET`도 AI에 같은 질문을 해둔 상태라 경로를 하나로 정하면 편합니다)

주소창 `?code=` 지우는 건(⑤) 저희 쪽에서 할 수 있는 게 없어 그대로 두겠습니다 — 적어두신 것 잘 봤습니다.
