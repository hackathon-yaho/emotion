# 대화를 끝내면 세션이 하나 더 열립니다 — 요약 화면이 대화 화면 밑에 중첩돼 있습니다

> **상태: ⏳ 회신 대기** (요청 2026-09-14)
> 회신은 `../../response/backend/summary-route-restarts-session.md`에 들어옵니다.
> **막고 있는 작업**: 없습니다. 홈 카드 증상은 백엔드가 v1.12로 막았습니다. 다만 **대화를 한 번 할 때마다 빈 세션이 하나씩 생기고**, 그 세션이 개인 임계 전환(F3-04)의 세션 수를 부풀립니다.

- 요청자: 백엔드
- 대상: 앱
- 관련: `../backend/open-session-used-time.md`(앱 → 백엔드)와 그 회신 `../../response/app/open-session-used-time.md` · 계약 v1.12 §2-2 · spec F2-05 · F3-04

## 한 줄

**「이어하기가 7분을 새로 준다」와 「끝낸 세션이 잠깐 열려 있음」은 원인이 같습니다.** 홈 카드가 가리킨 세션은 방금 끝낸 세션이 아닙니다. **종료 6~7초 뒤 앱이 새로 연 턴 0건 세션**입니다. 그 세션은 쓴 시간이 없으니 `usedSec = 0`이 맞는 값입니다.

## 실측 — 테스트 계정(`f707c165…`), 2026-09-14 KST

운영 DB `voice_session`·`turn_log`와 Hume 채팅 기록(`GET /v0/evi/chats`)을 맞춰 봤습니다.

| 세션 | 시작 → 종료 | 턴 | Hume 연결 |
| --- | --- | --- | --- |
| `1b07e2b9` | 20:47:47 → 20:48:57 `user_end` | 6 | 68초 |
| `4f9493e8` | **20:49:03** (종료 6초 뒤) | **0** | **1초** (20:49:04 → 05) |
| `39091ea0` | 23:17:09 → 23:19:18 `user_end` | 12 | 128초 |
| `b7cab295` | **23:19:25** (종료 7초 뒤) | **0** | 연결 없음. **아직 열려 있음** |

**두 번 모두 `종료 → 6~7초 → 턴 0건 새 세션`입니다.** 종료 응답은 요약 생성 때문에 몇 초 걸리고, `ended_at`은 종료 요청을 받은 시각입니다. 6~7초는 「종료 응답 → 요약 화면 → 세션 시작」에 맞는 간격입니다.

## 원인 — 요약 라우트가 `/conversation` 밑에 있습니다

1. 홈은 `context.push(Routes.conversation)`으로 대화 화면을 엽니다. **push로 연 페이지는 고유 키를 받습니다** — go_router 14.8.1 `parser.dart:181` `_getUniqueValueKey()`.
2. 종료하면 `_end()`가 `context.go(Routes.summary)`, 곧 `/conversation/summary`로 갑니다. 중첩 라우트이므로 go_router는 **부모 `/conversation` 페이지를 요약 아래에 새로 깝니다.** 이 페이지는 **경로 키**를 받습니다 — `match.dart:230` `ValueKey<String>(newMatchedPath)`.
3. **키가 다르니 Navigator는 같은 화면으로 보지 않고 새로 만듭니다.** `initState` → `_open()` → `me()`(방금 닫았으니 열린 세션 없음) → `startFreshSession` → **`POST /api/session/start`** → `_enter` → EVI 연결.
4. 요약에서 「홈으로」(`go(home)`)를 누르면 숨은 대화 화면은 dispose되지만, **종료 호출이 없으므로 서버 세션은 열린 채 남습니다.** 홈의 `/me`가 그 세션을 `openSession`으로 받아 「중단된 대화 · 남은 7분」을 띄웠습니다.

`b7cab295`에 연결 기록이 없는 것은, `startFreshSession`이 돌아오기 전에 화면이 사라져 `if (!mounted) return;`에 걸린 경우로 보입니다. 서버 세션만 생기고 소켓은 열리지 않은 것입니다.

## 영향

- **대화마다 빈 세션이 1건씩 생깁니다.** 이번 실측의 Hume 연결은 1초라 비용 영향은 작습니다.
- **빈 세션이 timeout으로 닫힐 때 `user_baseline.session_count`가 1 오릅니다.** 그러면 개인 임계 전환(F3-04, 5세션 이상)이 **실제 대화 3번 만에** 올 수 있고, `me.sessionCount`(탈퇴 문구)도 부풀어 오릅니다.
- 홈 카드는 **v1.12부터 백엔드가 턴 0건 세션을 `openSession`에서 빼므로 더 이상 뜨지 않습니다.** 증상만 가려질 뿐 원인은 그대로입니다.

## 부탁

**① 요약 화면으로 갈 때 대화 화면이 다시 만들어지지 않게 해주세요.** 요약 라우트를 `/conversation` 밖(예: 최상위 `/summary`)으로 옮기는 방법이 가장 단순해 보입니다. 방법은 앱에서 정하시면 되고, **확인 기준은 「대화를 끝낸 뒤 `POST /api/session/start`가 나가지 않는다」** 하나입니다.

**② `ConversationScreen.dispose()`가 EVI를 멈추는지 확인해 주세요.** 지금 코드는 `_eviSub`만 취소하고 `evi.stop()`을 부르지 않습니다. `_end`를 거치지 않고 화면이 사라지면 소켓이 남을 수 있습니다. 새 대화의 마이크 보류는 인사가 끝나면(인사가 오지 않으면 3.5초 뒤) 풀리므로, 소켓이 더 오래 붙어 있었다면 홈 화면에서 마이크 입력이 나갔을 수 있습니다. 이번에는 1초 만에 닫혀 실제 피해는 확인되지 않았습니다.

**③ 곁다리 「새로고침하면 사라졌다」는 이 원인으로 설명되지 않습니다.** 빈 세션은 30분 동안 열려 있으므로 새로고침해도 카드가 떠야 합니다. 그때 카드의 `sessionId`가 **끝낸 세션과 같았는지** 확인할 수 있으면 알려주세요. **다른 id였다면** `endedSessionIdProvider` 필터는 이 증상을 가린 적이 없고, 이제는 v1.12가 같은 역할을 합니다. **같은 id였다면** 별개 문제이니 다시 보겠습니다. 종료는 트랜잭션 커밋 뒤 응답하고 Supabase에는 읽기 복제본이 없어, 복제 지연은 아닙니다.
