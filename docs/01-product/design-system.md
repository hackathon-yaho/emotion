# 1. 방향 — 「밤의 활자」 + 「두 겹」

사용 맥락이 **늦은 밤·퇴근길의 혼잣말**이다(PRD §3.1). 화면이 사용자를 각성시키지 않아야 하고, 말하는 동안 시선을 끌지 않아야 한다.

**골격은 「밤의 활자」** — 지면에 가까운 언어다.

| 원칙 | 뜻 |
| --- | --- |
| **카드를 쓰지 않는다** | 구획은 **헤어라인과 여백**으로만 한다. 둥근 카드를 나열하면 어떤 앱과도 구분되지 않는다 |
| 활자가 일한다 | 관찰 문장은 **한글 명조**로 크게 둔다. 사용자가 읽어야 하는 유일한 문장이기 때문이다 |
| 색을 아낀다 | 강조색(호박)은 **누를 수 있는 라벨 한 곳**에만. 색으로 좋음/나쁨을 말하지 않는다 |
| 비어 있어도 된다 | 관찰이 없으면 빈 상태를 그대로 보여준다. 채우려고 만들지 않는다(FR-052) |
| 읽힌다 | 지친 눈으로 밤에 읽는다. 본문 16 미만으로 내려가지 않는다 |

**「두 겹」은 두 곳에만 쓴다.** 이 제품의 주제가 |텍스트 valence − 음성 valence|이므로, **갭이 실제 주제인 화면에서만** 어긋난 두 겹을 형태로 쓴다. 그 밖에서는 쓰지 않는다 — 남용하면 의미가 장식으로 떨어진다.

| 쓰는 곳 | 형태 |
| --- | --- |
| **S02 대화** | 어긋난 **두 개의 링** — 차가운 색(말한 내용) + 따뜻한 색(목소리). 어긋난 간격·크기·투명도만 상태에 반응하고 **색은 고정**이다 |
| **S04 추세** | 제목을 두 겹으로(뒤에 따뜻한 색 3px 오프셋). 그래프의 두 선이 이미 두 겹이라 제목이 그것을 예고한다 |

**두 겹은 그림자 한 겹으로 구현한다** — 같은 텍스트를 두 벌 겹치지 않는다. 오프셋 `3px 3px`, 흐림 0, 색은 목소리 채널의 따뜻한 색(다크 90% · 라이트 65%). Flutter에서는 `Text`의 `shadows`에 같은 값을 준다.

> **두 벌을 겹치는 방식은 쓰지 않는다.** 처음에 절대 위치 사본과 흐름 속 사본을 겹쳤더니 **세로 오프셋이 3px가 아니라 6px·4px로 어긋났다** — 한쪽은 `line-height` 박스, 다른 쪽은 폰트 메트릭 박스를 기준으로 잡혀서 폰트 크기·행간마다 값이 달라진다. 사본이 하나면 이 실패가 구조적으로 불가능하다.

# 2. 레이아웃 — 하나만 만든다

**모바일 폭 캔버스를 데스크톱에서는 중앙에 고정한다.** 태블릿·데스크톱 전용 레이아웃을 만들지 않는다.

```
[ >= 600 ]                        [ < 600 ]
┌────────────────────────────┐    ┌──────────┐
│        배경 (bg)            │    │  전폭     │
│      ┌──────────────┐      │    │  앱 셸    │
│      │  앱 셸        │      │    │          │
│      │  max 420     │      │    │          │
│      │ [하단 탭 4]   │      │    │[하단 탭] │
│      └──────────────┘      │    └──────────┘
└────────────────────────────┘
```

| 항목 | 값 |
| --- | --- |
| 디자인 기준 | **390 × 844** (논리 픽셀) |
| 앱 셸 최대 폭 | **420** |
| 분기점 | **600 하나만.** `< 600` 전폭 / `>= 600` 중앙 고정 + 배경 |
| 하단 탭 | 홈 · 발견 · 트렌드 · 기록 (spec §4 공통 요소) |

**분기점을 하나만 두는 이유** — 폭마다 레이아웃을 나누면 검증할 화면이 11개에서 배로 늘어난다. 실제 사용 환경은 **도그푸딩(휴대폰 브라우저)과 심사 시연(데스크톱)** 둘뿐이고, 데스크톱은 매일 쓰는 환경이 아니라 보여주는 환경이다.

## 2-1. 넓은 화면에서 확장하는 예외 두 곳

| 화면 | 확장 이유 |
| --- | --- |
| **S04 트렌드 (두 선 그래프)** | 제품의 서명 화면. 심사장 프로젝터에서 **뒷줄까지 두 선이 갈라진 것이 보여야** 한다. `>= 600`에서 셸 폭을 넘겨 가로만 확장하고, 축 범위(−1~+1)와 세로 비율은 유지 |
| **데모 모드 오버레이 (S02)** | 4개 수치를 프로젝터에서 읽혀야 한다. `< 600` 상단 배지 / `>= 600` 셸 오른쪽 패널 |

나머지 화면은 목록·본문·시트라서 좁은 폭이 오히려 읽기 좋다. 넓히면 시선 이동만 길어진다.

# 3. 사이징 스케일

Flutter는 캔버스에 직접 그려 CSS의 `rem`이 없다. **논리 픽셀 고정값을 스케일로 정해두고 전 화면에서 그것만 쓴다.**

| 종류 | 값 |
| --- | --- |
| 간격 | **4의 배수** — 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 화면 좌우 여백 | **20** 고정. §2-1의 넓은 화면 확장 아트보드만 **40** |
| 본문 | **16** (하한. 15 이하로 내리지 않는다) |
| 보조·캡션 | 13 ~ 14 |
| 화면 제목 | 24 ~ 28 |
| 탭 라벨 | 12 |
| 차트 축·틱 라벨 | 12 |
| 터치 타깃 | **최소 48 × 48** |
| 모서리 | **버튼·입력 2** (거의 사각 — 활자 중심 언어에 맞춘다) · **바텀시트 상단 20** · 링은 원. 카드가 없으므로 카드 반경도 없다 |
| 폰트 | **두 종.** 관찰 문장·화면 제목·109 번호는 **한글 명조**(Gowun Batang), 나머지 전부는 **산세리프**(Pretendard 계열). 셋째 서체를 넣지 않는다 |
| 라벨 자간 | 작은 라벨(11~12)은 **자간 0.14em**. 명조 제목은 자간 0 |
| 캔버스 대체 | 디자인 캔버스는 Google Fonts만 불러올 수 있어 산세리프를 **Noto Sans KR로 대체**해 그렸다. 실제 앱에서는 Pretendard를 쓴다 |

# 4. 색 토큰 — 다크·라이트 둘 다

기본값은 **시스템 설정을 따르고**(Flutter Web은 `MediaQuery.platformBrightness`), S06 설정에서 수동 전환한다.

| 역할 | 다크 | 라이트 |
| --- | --- | --- |
| `bg` (배경) | `#0D0D0C` | `#F5F2EC` |
| `lift` (시트·오버레이 **전용**) | `#161614` | `#FFFFFF` |
| `paper` (본문) | `#F2EFE9` | `#1A1815` |
| `muted` (보조 본문) | `#8A8781` | `#6B675F` |
| `faint` (라벨·비활성) | `#55534E` | `#9A968D` |
| `line` (헤어라인) | `rgba(242,239,233,0.12)` | `rgba(26,24,21,0.14)` |
| `accent` (동작 · 호박) | `#C98A4B` | `#8A5A22` |
| `care` (S07 위기 안내) | `#C98087` | `#A85A62` |
| `shade` (갭 구간 음영) | `rgba(242,239,233,0.07)` | `rgba(26,24,21,0.06)` |

**규칙 넷**

- **`lift`는 시트·오버레이에만 쓴다.** 카드 배경으로 쓰면 「카드를 쓰지 않는다」가 무너진다.
- **본문·캡션 텍스트에 `accent`·`care`·그래프 색을 쓰지 않는다.** 읽는 텍스트는 항상 `paper`·`muted`·`faint`다. **예외는 누를 수 있는 라벨** — 링크, "근거 보기" 같은 동작 라벨은 `accent`.
- **`care`는 S07 전용이다.** 데모 배지·강조 같은 다른 용도로 쓰지 않는다 — 예약된 색이 흔해지면 정작 필요한 순간에 아무 신호도 되지 못한다.
- **라이트는 다크의 자동 반전이 아니다.** 각 모드에서 따로 고른 값이며, 위 표의 쌍이 그 결과다.

## 4-1. `care` 색에 빨강을 쓰지 않는 이유

S07은 위기 감지 시 뜨는 안내다. 여기에 경고 빨강을 쓰면 화면이 **"당신은 위험한 상태입니다"라고 단정**하는 셈이 된다. 이 제품은 절대 감정을 단정하지 않고(FR-022), 위기 감지 시에도 **대화를 끊지 않고 곁에 있는 것**이 설계 의도다(FR-033). 따뜻한 로즈 계열을 쓰고, 시트는 경고창이 아니라 **손을 내미는 카드**로 보이게 한다. 뒤에 대화 화면을 흐리게 남겨 "대화는 계속되고 있습니다"가 보이게 한다.

## 4-2. 카카오 로그인 버튼은 예외다

카카오 로그인 버튼은 **카카오 브랜드 가이드를 따른다.** 우리 색·모서리 규칙(호박 강조, 모서리 2)의 유일한 예외다.

| 항목 | 값 |
| --- | --- |
| 배경 | **`#FEE500`** (카카오 옐로우) |
| 텍스트 | **검정 85%** (`rgba(0,0,0,0.85)`) |
| 모서리 | 6 |
| 높이 | 54 (터치 타깃 하한 48 충족) |
| 라벨 | `카카오로 시작하기` (spec F1-01의 트리거 문구와 일치시킨다) |

**임의로 색을 바꾸거나 다크 테마에 맞춰 변형하지 않는다.** 소셜 로그인 버튼은 제공자가 규정한 형태를 쓰는 것이 전제다. 다크 화면에서 유일하게 튀는 요소가 되지만, S00에서만 나타나고 그 화면의 유일한 동작이므로 문제가 아니다.

**심볼은 공식 애셋으로 교체한다.** 캔버스의 말풍선은 자리를 잡아둔 대체 도형이다 — 구현 시 카카오 디벨로퍼스에서 받은 공식 이미지를 쓴다.

## 4-3. 웹 배포 때문에 생긴 제약 — 109 통화

`tel:` 링크는 휴대폰에서만 걸린다. **번호를 크게 표시하고 복사 버튼을 함께** 두며, 전화가 가능한 환경에서만 통화 버튼이 의미를 갖는다. spec F4-04의 "통화 연결 버튼"만으로는 데스크톱 시연에서 무의미하다.

# 5. 트렌드 그래프 (S04) — 검증된 색

두 선은 **텍스트 valence**와 **음성 valence**다. 같은 척도(−1~+1)이므로 **축은 하나**다 — 이중 축을 쓰지 않는다.

| 계열 | 다크 | 라이트 | 의미 |
| --- | --- | --- | --- |
| **텍스트 valence** (`cool`) | `#5A8FC9` | `#2F6FA8` | 말한 내용 — 차가운 쪽 |
| **음성 valence** (`warm`) | `#C25A38` | `#B5411F` | 목소리 — 따뜻한 쪽 |

이 두 색은 S02 대화의 **두 링에도 같은 의미로** 쓰인다. 제품 전체에서 차가운 색은 말한 내용, 따뜻한 색은 목소리다.

**검증 결과** (dataviz 검증기, 2026-09-03 · 팔레트 교체 후 재측정)

| 검사 | 다크 (surface `#0D0D0C`) | 라이트 (surface `#F5F2EC`) |
| --- | --- | --- |
| 명도 밴드 | PASS | PASS |
| 채도 하한 | PASS | PASS |
| 색각이상 분리 | PASS — ΔE 20.2 (deutan) | PASS — ΔE 20.0 (protan) |
| 정상시야 분리 | PASS — ΔE 24.1 | PASS — ΔE 25.9 |
| 표면 대비 | PASS (≥ 3:1) | PASS (≥ 3:1) |

> 첫 팔레트(`#3987E5`/`#D95926`)는 배경이 남색에서 따뜻한 검정으로 바뀌면서 명도·채도 밴드를 벗어났다. **배경을 바꾸면 계열 색도 다시 측정한다** — 눈으로 판단하지 않는다.

**그리기 규약**

| 항목 | 값 |
| --- | --- |
| 선 두께 | 2 |
| 마커 | **지름 8 이상**(반지름 4) — 데이터 있는 날만 |
| 축 범위 | **−1.00 ~ +1.00 고정** (F9-01 수용 기준) |
| **없는 날** | **선을 끊는다.** 0으로 채우거나 보간하지 않는다 — 없는 감정을 그리는 것이기 때문(계약서 §1-3) |
| 갭 구간 강조 | `highlights` 구간을 **중립 회색 음영**으로. 음영의 좌우 경계는 **점 중심이 아니라 반 보폭 밖**에 둔다(경계에 걸친 점이 어느 쪽인지 모호해지지 않게). 색으로 좋음/나쁨을 말하지 않는다. 탭하면 그날 대화 상세(S05-1)로 이동(F9-02) |
| 범례 | 2계열이므로 **항상 표시** + 두 선에 직접 라벨. 색만으로 구분되게 두지 않는다 |
| 격자·축 | 후퇴시킨다 (`border` 톤) |
| 호버·탭 | 크로스헤어 + 툴팁. 그날의 두 값과 갭을 보여준다 |

# 6. S02 대화 화면 — 그려도 되는 것과 안 되는 것

갭·valence를 그릴 수 없어서(FR-031) 화면에 놓을 것이 거의 없다. **여기서 가장 쉬운 사고는 "감정을 은근히 시각화하는 연출"이다.**

| 금지 | 이유 |
| --- | --- |
| 배경색·조명이 감정에 따라 변한다 | 사용자가 "화면이 어두워졌네"로 읽는 순간 **사실상 갭 노출**이다. FR-030이 막으려던 "관찰당하는 느낌"이 그대로 생긴다 |
| 파형·원의 색이 valence에 반응한다 | 위와 같다 |
| 갭·valence 수치·게이지 | FR-031. `demoMode == true`일 때만 예외 |

| 허용 | 내용 |
| --- | --- |
| **음성 연결 상태** | 듣는 중 / AI가 말하는 중 / 연결 중 — 감정이 아니라 **연결**을 그린다 |
| 입력 레벨 | 소리가 들어오고 있다는 것만. 크기에만 반응하고 **색은 고정** |
| **사용자 발화 자막** | 아래 6-1 |

## 6-1. 전사(자막) 표시 — 절충안 확정

**사용자 발화만 짧게 보이고 사라진다. AI 응답은 화면에 남기지 않는다.**

| 항목 | 내용 |
| --- | --- |
| 표시 | 사용자 발화가 전사되면 한두 줄로 나타나고, 다음 발화가 오면 교체된다 |
| 남기지 않음 | 채팅 로그처럼 쌓지 않는다 |
| AI 응답 | 자막 없음 — **목소리로만** |
| 근거 | 완전히 비우면 "내 말이 전달됐나"가 불안하고, 채팅 로그로 쌓으면 **"말로 하는 저널"이 텍스트 채팅과 구분되지 않는다.** 지난 대화는 S05-1에서 전문으로 읽을 수 있으므로 대화 중에 남길 이유가 없다 |

# 7. 나머지 UX 결정 (앱 담당 확정, 2026-09-03)

되돌릴 수 있는 결정이며, 근거가 바뀌면 이 문서를 고친다.

| # | 항목 | 결정 |
| --- | --- | --- |
| 1 | **세션 타이머** | 평소 **숨긴다.** 소프트 랩(5분)은 AI가 말로 유도하므로 UI가 필요 없다(F2-03). **하드컷 60초 전부터** 조용한 표시만 띄운다 — 남은 시간을 계속 보여주면 털어놓는 데 압박이 된다 |
| 2 | **온보딩 동의 기록** | **로컬 플래그 우선, `isNewUser`는 보조.** `isNewUser`는 로그인 응답으로 오는데 F1-05는 **로그인 전** 노출을 요구하므로 그것만으로는 성립하지 않는다. 브라우저 저장소가 비면 다시 노출되는 쪽이 안전한 방향이다 |
| 3 | **S07 109 안내** | **번호를 크게 표시 + 복사 버튼**을 기본으로 하고, 전화가 가능한 환경에서만 통화 버튼을 함께 둔다. 웹 배포라 **데스크톱에서는 `tel:`이 동작하지 않는다** — spec F4-04의 "통화 연결 버튼"만으로는 시연 환경에서 무의미하다 |
| 4 | **데모 모드 표시** | `< 600` 상단 배지 / `>= 600` 셸 오른쪽 패널. 텍스트 valence · 음성 valence · 갭 · 트리거 여부 4개 (F11-01) |
| 5 | **F2-04 오류 문구** | 원인별 3분기. 아래 7-1 |

| 6 | **하단 탭 라벨** | **오늘 · 발견 · 추세 · 기록.** spec §4의 "홈·트렌드"를 디자인 언어에 맞춰 바꿨다(spec §4 갱신됨). 화면 ID·화면명은 그대로 |
| 7 | **S02-1 종료 요약의 `gapAvg`** | **표시하지 않는다.** 계약서 종료 응답에 있지만 FR-031이 갭을 "기록·트렌드 화면에서만"이라 했다. 대화를 마친 직후에 숫자를 보이는 것은 대화 화면의 연장으로 읽힌다 |
| 8 | **S05 기록 항목** | `tags`(상위 3개)·`gapAvg`를 **표시한다.** 기록 화면은 갭 노출이 허용되고(FR-031), 목록에서 그날의 주제와 갭을 한눈에 훑을 수 있어야 상세로 들어갈 이유가 생긴다 |
| 9 | **S03-1 근거 턴** | 갭만이 아니라 **텍스트·음성 valence를 둘 다** 표시한다. "근거"라면 갭이 어디서 왔는지가 보여야 한다 |
| 10 | **로딩 상태** | 스켈레톤은 **헤어라인 굵기의 가는 막대**로, `hair` 색에 느린 명멸. 카드 모양 스켈레톤을 쓰지 않는다 — 카드가 없는 언어에서 카드 실루엣이 뜨면 로딩이 끝난 뒤 화면이 달라진다 |
| 11 | **빈 상태** | **명조를 쓰지 않는다.** 명조는 실제로 발견된 문장에만 쓰는 서체다. 빈 상태는 산세리프 `muted`로, 억지 문구 없이 **조건을 정직하게** 말한다(§7-1). 빈 그래프·빈 카드 실루엣을 그리지 않는다 |
| 12 | **파괴적 동작(탈퇴·삭제)의 색** | **`care`를 쓰지 않는다** — `care`는 S07 전용이다(§4). 경고는 **문장**이 하고, 확인 시트에서는 **안전한 선택(취소)을 채운 버튼**으로, 파괴적 선택은 테두리만 둔 버튼으로 둔다. 실수로 누르기 어렵게 |
| 14 | **F2-07 이어하기 표현** | 홈(S01)에 "중단된 대화" 블록 — 문장 + **남은 시간(7분에서 이미 쓴 시간을 뺀 값)** + [이어서 하기](채움) [새로 시작](테두리). 대화 화면(S02)에는 첫 상태에 "이어서 이야기합니다 · 남은 시간 N분"을 한 줄만. 30분 창이 지난 경우(409)는 같은 자리에 "이어갈 수 있는 시간이 지났습니다. 새 대화로 시작합니다." 후 평소 CTA |
| 15 | **F7-08 피드백 선택 후** | 버튼 두 개가 사라지고 **'"맞아요"로 답했습니다'** 한 줄이 `faint`로 남는다. 취소·수정 없음(spec F7-08). 답이 관찰을 지우지 않는다는 것이 화면에서도 읽혀야 한다 — 문장·evidence는 그대로 |
| 16 | **F9-03 이야기별 갭 막대** | 가로 막대, 세 번 이상 나온 이야기만(서버가 이미 제외). **세로 실선 = 내 평균, 점선 = ×1.5.** 둘을 넘은 막대만 `paper`, 나머지는 `faint` — 코드의 판정 기준(FR-051)을 그대로 보여주는 것이며 좋음/나쁨 색이 아니다. 막대는 6px, 모서리 2. 갭은 채널이 아니므로 `cool`/`warm`을 쓰지 않는다 |
| 17 | **기간 선택과 밀도** | 7일 · 30일 · 90일. x축 라벨은 **8개 안팎**으로 자동 간격(끝 날짜는 항상). **마커는 점 간격이 14px 이상일 때만** 그린다 — 90일에서는 겹치므로 선만. 호버 크로스헤어·툴팁은 모든 기간에서 동작 |
| 19 | **`TrendPoint.sessionCount`** | 하루에 2세션 이상인 날은 **점 위에 작은 표식**을 두고 툴팁에 "2회 평균"을 적는다. 계약서 §2-8이 "그날의 **평균**"이라고 규정했는데 그 사실이 화면에 없으면 그래프를 잘못 읽는다 |
| 20 | **`Observation.createdAt`** | 발견 목록(S03) 각 항목에 **발견된 날짜**를 라벨로 둔다. 정렬이 최신순이므로(§1-4) 날짜가 없으면 순서의 의미가 보이지 않는다 |
| 21 | **`SessionDetail.endReason`** | 상세(S05-1) 머리말에 **`hard_cut`·`timeout`일 때만** 한 줄로 적는다 ("7분에 자동으로 마무리됐습니다" / "연결이 끊겨 정리됐습니다"). `user_end`는 적지 않는다 — 당연한 것을 적으면 노이즈다 |
| 22 | **목록 페이징** | 기본 20개(계약서 §1-4), 바닥에 닿으면 이어서 불러온다. **"더 보기" 버튼을 두지 않는다** — 조용한 언어에 버튼이 하나 더 붙을 이유가 없다. 남은 개수는 표시하지 않고, 마지막에 닿으면 조용히 끝난다 |
| 23 | **문구 톤** | 화면 문구는 **"-습니다"** 로 통일한다. 「밤의 활자」의 지면 같은 어조에 맞고, "-어요"보다 사용자를 덜 다그친다. §7-1의 문구도 이 톤으로 다시 썼다 |

## 7-1. 오류·빈 상태 문구

서버 오류는 계약서 §1-2의 `message`를 그대로 보여준다. **아래는 서버가 주지 않는 것들**(기기·SDK 사유)이라 앱이 쓴다.

| 상황 | 문구 | 동작 |
| --- | --- | --- |
| 마이크 권한 거부 (S02) | "마이크를 사용할 수 없습니다. 브라우저 설정에서 이 사이트의 마이크를 허용해 주세요." | 설정 안내 |
| 네트워크 끊김 (S02) | "연결이 끊어졌습니다. 다시 연결해 볼까요?" | **다시 연결** 버튼 |
| EVI 장애 (S02) | "지금은 대화를 시작할 수 없습니다. 잠시 후 다시 시도해 주세요." | **다시 시도** 버튼 |
| Hume 토큰 발급 실패 (S01 CTA, 503) | "지금은 대화를 시작할 수 없습니다. 잠시 후 다시 시도해 주세요." | CTA가 **다시 시도**로 바뀜. 대화 시작 차단 |
| 관찰 0건 (S01) | "아직 발견한 것이 없습니다. 대화가 쌓이면 여기에 보입니다." | 억지 문구를 만들지 않는다(FR-052) |
| 관찰 0건 (S03) | 위 문구 + "같은 이야기가 세 번 이상 나오고, 그때 목소리가 평소와 달라야 발견으로 칩니다." | 조건을 정직하게 말한다(FR-051) |
| 트렌드 데이터 없음 (S04) | "아직 그릴 기록이 없습니다. 대화가 쌓이면 말한 내용과 목소리를 나란히 보여드립니다." | 빈 그래프를 그리지 않는다 |
| 대화 기록 없음 (S05) | "아직 대화가 없습니다." | — |
| 지난 대화 없음 (S01) | "첫 대화를 기다리고 있습니다." | — |
| 탈퇴 확인 (S06) | "계정을 지울까요?" / "대화 N건과 발견 N건이 지금 바로 모두 지워집니다. 유예 기간이 없고 되돌릴 수 없습니다. 같은 카카오 계정으로 다시 시작하면 새 사용자가 됩니다." | **취소**(채움) / **모두 지우고 탈퇴**(테두리) |

**어떤 경우에도 앱이 멈추거나 흰 화면이 되지 않는다**(F2-04 수용 기준). Hume 공식 예제는 인증 실패·마이크 거부에서 처리되지 않은 예외를 던지므로 **이 경로는 새로 작성한다**(실측 확인, PRD §14-4).
