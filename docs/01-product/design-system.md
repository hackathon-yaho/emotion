# 1. 방향 — "차분한 밤"

사용 맥락이 **늦은 밤·퇴근길의 혼잣말**이다(PRD §3.1). 화면이 사용자를 각성시키지 않아야 하고, 말하는 동안 시선을 끌지 않아야 한다.

| 원칙 | 뜻 |
| --- | --- |
| 조용하다 | 강한 채도·큰 그림자·애니메이션 없음. 움직이는 것은 음성 상태 표시 하나뿐 |
| 판단하지 않는다 | 색으로 좋음/나쁨을 말하지 않는다. 경고색·위험색을 감정에 쓰지 않는다 |
| 읽힌다 | 지친 눈으로 밤에 읽는다. 본문 16 미만으로 내려가지 않는다 |
| 비어 있어도 된다 | 관찰이 없으면 빈 상태를 그대로 보여준다. 채우려고 만들지 않는다(FR-052) |

# 2. 레이아웃 — 하나만 만든다

**모바일 폭 캔버스를 데스크톱에서는 중앙에 고정한다.** 태블릿·데스크톱 전용 레이아웃을 만들지 않는다.

```
[ >= 600 ]                        [ < 600 ]
┌────────────────────────────┐    ┌──────────┐
│        배경 (bg)            │    │  전폭     │
│      ┌──────────────┐      │    │  앱 셸    │
│      │  앱 셸        │      │    │          │
│      │  max 420     │      │    │          │
│      │ [하단 탭 4]   │      │    │[하단 탭] │
│      └──────────────┘      │    └──────────┘
└────────────────────────────┘
```

| 항목 | 값 |
| --- | --- |
| 디자인 기준 | **390 × 844** (논리 픽셀) |
| 앱 셸 최대 폭 | **420** |
| 분기점 | **600 하나만.** `< 600` 전폭 / `>= 600` 중앙 고정 + 배경 |
| 하단 탭 | 홈 · 발견 · 트렌드 · 기록 (spec §4 공통 요소) |

**분기점을 하나만 두는 이유** — 폭마다 레이아웃을 나누면 검증할 화면이 11개에서 배로 늘어난다. 실제 사용 환경은 **도그푸딩(휴대폰 브라우저)과 심사 시연(데스크톱)** 둘뿐이고, 데스크톱은 매일 쓰는 환경이 아니라 보여주는 환경이다.

## 2-1. 넓은 화면에서 확장하는 예외 두 곳

| 화면 | 확장 이유 |
| --- | --- |
| **S04 트렌드 (두 선 그래프)** | 제품의 서명 화면. 심사장 프로젝터에서 **뒷줄까지 두 선이 갈라진 것이 보여야** 한다. `>= 600`에서 셸 폭을 넘겨 가로만 확장하고, 축 범위(−1~+1)와 세로 비율은 유지 |
| **데모 모드 오버레이 (S02)** | 4개 수치를 프로젝터에서 읽혀야 한다. `< 600` 상단 배지 / `>= 600` 셸 오른쪽 패널 |

나머지 9개 화면은 목록·카드·시트라서 좁은 폭이 오히려 읽기 좋다. 넓히면 시선 이동만 길어진다.

# 3. 사이징 스케일

Flutter는 캔버스에 직접 그려 CSS의 `rem`이 없다. **논리 픽셀 고정값을 스케일로 정해두고 전 화면에서 그것만 쓴다.**

| 종류 | 값 |
| --- | --- |
| 간격 | **4의 배수** — 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 화면 좌우 여백 | **20** 고정 |
| 본문 | **16** (하한. 15 이하로 내리지 않는다) |
| 보조·캡션 | 13 ~ 14 |
| 화면 제목 | 24 ~ 28 |
| 탭 라벨 | 12 |
| 터치 타깃 | **최소 48 × 48** |
| 모서리 | 카드 16 · 버튼 12 · 바텀시트 상단 20 |
| 폰트 | **Pretendard 계열 한 종.** 본문이 읽히는 게 전부이므로 섞지 않는다 |

# 4. 색 토큰 — 다크·라이트 둘 다

기본값은 **시스템 설정을 따르고**(Flutter Web은 `MediaQuery.platformBrightness`), S06 설정에서 수동 전환한다.

| 역할 | 다크 | 라이트 |
| --- | --- | --- |
| `bg` (배경) | `#12161C` | `#F6F7F9` |
| `surface` (카드·시트) | `#191E26` | `#FFFFFF` |
| `surface-raised` | `#212832` | `#FFFFFF` (+ border) |
| `border` | `#2C3441` | `#E2E6EC` |
| `text-primary` | `#E7EAEF` | `#14181F` |
| `text-secondary` | `#9BA6B4` | `#5A6472` |
| `text-muted` | `#6B7684` | `#8A94A2` |
| `accent` (주요 동작·연결 상태) | `#8FB0E6` | `#2F62A8` |
| `care` (S07 위기 안내) | `#E0A15E` | `#B0742C` |

**규칙 두 개**

- **본문 텍스트에 `accent`·`care`·그래프 색을 쓰지 않는다.** 텍스트는 항상 ink 토큰(`text-*`)이고, 색은 옆의 마크가 담당한다.
- **라이트는 다크의 자동 반전이 아니다.** 각 모드에서 따로 고른 값이며, 위 표의 쌍이 그 결과다.

## 4-1. `care` 색에 빨강을 쓰지 않는 이유

S07은 위기 감지 시 뜨는 안내다. 여기에 경고 빨강을 쓰면 화면이 **"당신은 위험한 상태입니다"라고 단정**하는 셈이 된다. 이 제품은 절대 감정을 단정하지 않고(FR-022), 위기 감지 시에도 **대화를 끊지 않고 곁에 있는 것**이 설계 의도다(FR-033). 따뜻한 앰버 계열을 쓰고, 시트는 경고창이 아니라 **손을 내미는 카드**로 보이게 한다.

# 5. 트렌드 그래프 (S04) — 검증된 색

두 선은 **텍스트 valence**와 **음성 valence**다. 같은 척도(−1~+1)이므로 **축은 하나**다 — 이중 축을 쓰지 않는다.

| 계열 | 다크 | 라이트 | 의미 |
| --- | --- | --- | --- |
| **텍스트 valence** | `#3987E5` | `#2A78D6` | 말한 내용 — 차가운 쪽 |
| **음성 valence** | `#D95926` | `#D95926` | 목소리 — 따뜻한 쪽 |

**검증 결과** (dataviz 검증기, 2026-09-03)

| 검사 | 다크 (surface `#12161C`) | 라이트 (surface `#F6F7F9`) |
| --- | --- | --- |
| 명도 밴드 | PASS | PASS |
| 채도 하한 | PASS | PASS |
| 색각이상 분리 | PASS — ΔE 26.8 (protan) | PASS — ΔE 25.4 (protan) |
| 정상시야 분리 | PASS — ΔE 31.8 | PASS — ΔE 32.3 |
| 표면 대비 | PASS (≥ 3:1) | PASS (≥ 3:1) |

**그리기 규약**

| 항목 | 값 |
| --- | --- |
| 선 두께 | 2 |
| 마커 | 8 이상 (데이터 있는 날만) |
| 축 범위 | **−1.00 ~ +1.00 고정** (F9-01 수용 기준) |
| **없는 날** | **선을 끊는다.** 0으로 채우거나 보간하지 않는다 — 없는 감정을 그리는 것이기 때문(계약서 §1-3) |
| 갭 구간 강조 | `highlights` 구간을 **중립 회색 음영**으로. 색으로 좋음/나쁨을 말하지 않는다. 탭하면 그날 대화 상세(S05-1)로 이동(F9-02) |
| 범례 | 2계열이므로 **항상 표시** + 두 선에 직접 라벨. 색만으로 구분되게 두지 않는다 |
| 격자·축 | 후퇴시킨다 (`border` 톤) |
| 호버·탭 | 크로스헤어 + 툴팁. 그날의 두 값과 갭을 보여준다 |

# 6. S02 대화 화면 — 그려도 되는 것과 안 되는 것

갭·valence를 그릴 수 없어서(FR-031) 화면에 놓을 것이 거의 없다. **여기서 가장 쉬운 사고는 "감정을 은근히 시각화하는 연출"이다.**

| 금지 | 이유 |
| --- | --- |
| 배경색·조명이 감정에 따라 변한다 | 사용자가 "화면이 어두워졌네"로 읽는 순간 **사실상 갭 노출**이다. FR-030이 막으려던 "관찰당하는 느낌"이 그대로 생긴다 |
| 파형·원의 색이 valence에 반응한다 | 위와 같다 |
| 갭·valence 수치·게이지 | FR-031. `demoMode == true`일 때만 예외 |

| 허용 | 내용 |
| --- | --- |
| **음성 연결 상태** | 듣는 중 / AI가 말하는 중 / 연결 중 — 감정이 아니라 **연결**을 그린다 |
| 입력 레벨 | 소리가 들어오고 있다는 것만. 크기에만 반응하고 **색은 고정** |
| **사용자 발화 자막** | 아래 6-1 |

## 6-1. 전사(자막) 표시 — 절충안 확정

**사용자 발화만 짧게 보이고 사라진다. AI 응답은 화면에 남기지 않는다.**

| 항목 | 내용 |
| --- | --- |
| 표시 | 사용자 발화가 전사되면 한두 줄로 나타나고, 다음 발화가 오면 교체된다 |
| 남기지 않음 | 채팅 로그처럼 쌓지 않는다 |
| AI 응답 | 자막 없음 — **목소리로만** |
| 근거 | 완전히 비우면 "내 말이 전달됐나"가 불안하고, 채팅 로그로 쌓으면 **"말로 하는 저널"이 텍스트 채팅과 구분되지 않는다.** 지난 대화는 S05-1에서 전문으로 읽을 수 있으므로 대화 중에 남길 이유가 없다 |

# 7. 나머지 UX 결정 (앱 담당 확정, 2026-09-03)

되돌릴 수 있는 결정이며, 근거가 바뀌면 이 문서를 고친다.

| # | 항목 | 결정 |
| --- | --- | --- |
| 1 | **세션 타이머** | 평소 **숨긴다.** 소프트 랩(5분)은 AI가 말로 유도하므로 UI가 필요 없다(F2-03). **하드컷 60초 전부터** 조용한 표시만 띄운다 — 남은 시간을 계속 보여주면 털어놓는 데 압박이 된다 |
| 2 | **온보딩 동의 기록** | **로컬 플래그 우선, `isNewUser`는 보조.** `isNewUser`는 로그인 응답으로 오는데 F1-05는 **로그인 전** 노출을 요구하므로 그것만으로는 성립하지 않는다. 브라우저 저장소가 비면 다시 노출되는 쪽이 안전한 방향이다 |
| 3 | **S07 109 안내** | **번호를 크게 표시 + 복사 버튼**을 기본으로 하고, 전화가 가능한 환경에서만 통화 버튼을 함께 둔다. 웹 배포라 **데스크톱에서는 `tel:`이 동작하지 않는다** — spec F4-04의 "통화 연결 버튼"만으로는 시연 환경에서 무의미하다 |
| 4 | **데모 모드 표시** | `< 600` 상단 배지 / `>= 600` 셸 오른쪽 패널. 텍스트 valence · 음성 valence · 갭 · 트리거 여부 4개 (F11-01) |
| 5 | **F2-04 오류 문구** | 원인별 3분기. 아래 7-1 |

## 7-1. 오류·빈 상태 문구

서버 오류는 계약서 §1-2의 `message`를 그대로 보여준다. **아래는 서버가 주지 않는 것들**(기기·SDK 사유)이라 앱이 쓴다.

| 상황 | 문구 | 동작 |
| --- | --- | --- |
| 마이크 권한 거부 | "마이크를 사용할 수 없어요. 브라우저 설정에서 이 사이트의 마이크를 허용해 주세요." | 설정 안내 |
| 네트워크 끊김 | "연결이 끊겼어요. 잠시 후 다시 시도해 주세요." | 재시도 버튼 |
| EVI 장애 | "지금은 대화를 시작할 수 없어요. 잠시 후 다시 시도해 주세요." | 재시도 버튼 |
| 관찰 0건 (S01·S03) | "아직 발견된 패턴이 없어요. 대화가 쌓이면 알려드릴게요." | 억지 문구를 만들지 않는다(FR-052) |
| 트렌드 데이터 없음 (S04) | "아직 그릴 기록이 없어요." | 빈 그래프를 그리지 않는다 |

**어떤 경우에도 앱이 멈추거나 흰 화면이 되지 않는다**(F2-04 수용 기준). Hume 공식 예제는 인증 실패·마이크 거부에서 처리되지 않은 예외를 던지므로 **이 경로는 새로 작성한다**(실측 확인, PRD §14-4).
